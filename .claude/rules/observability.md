# Observability Features (§8.19–§8.34)

> Loaded only when touching observability code. Rules only — rationale, history, measurements and full rot-guard lists live in `.claude/references/design-notes/<section>-*.md`; read the note before changing that area. §8.25 (notifiers / post-commit rule) and §8.33 (append-only outcome stats, worker lockstep) are always loaded from `project-specific.md`.

## Shared shape (applies to every surface below)

- **Telemetry always emits; DB recording is opt-in.** Spans + meters fire unconditionally (null-listener, zero cost); rows are written only where the host opted in.
- **Entities are always in the schema** (§2.11, `WarpModelCustomizer`) and mirrored by Warp's own contexts (§2.14); builder methods gate runtime behaviour only. Entities live in `Warp.Core.Data.Entities` (§8.13). Migrations are additive.
- **Read services are registered by `AddWarp` itself** so dashboard-only / publisher-only processes resolve them. Query services read on the Warp context (`IWarpContext`); server tasks write on the server context (§2.14).
- **Recording pipelines are lossy by design** (`DrainQueue`/`DrainService`, §2.19): a full channel drops the record and counts it (§8.32); user calls/requests are never blocked or failed.
- **Durable metrics go `Counter` → `CounterAggregator` → `Statistic`** (worker path: `WarpCounterBuffer`, §6.2) so counts/error-rate/latency survive raw-row cleanup. Never write `Statistic` from a hot path.
- **Counter-key namespaces are disjoint by first segment** (`adapter-app`, `endpoint-app`, `jobstat`/`jobstat-app`, `qwait`/`qwait-app`, `qbacklog`, `clientevent`/`clientevent-app`, `errorgroup`/`errorgroup-app`, `warpsys`, `deadline`): add new slices under a NEW prefix, never change an existing key.
- **Cardinality guards on anything unbounded** collapse overflow to `{other}`, warn once, and never put a raw value in a report (§1.2). Client-sent values are never trusted bounded.
- **PII (§1.2):** captured bodies/headers are opt-in per tier (`None`/`OnFailure`/`Always`), truncated and passed through the user-owned `RedactedHeaders` denylist; never log captured content at Info+.
- **Worker hot path untouched (§0.2/§6.1)** — at most an in-memory increment/meter at an existing finalization site, in BOTH worker modes (§8.33).
- **Dashboard nav flags** (`GET {prefix}/api/addons`) key on presence markers registered regardless of sink.

## Surfaces

- **§8.19** **Outbound adapters** (`Warp.Core.Adapters`; bindings `Warp.Adapters.Http`, `Warp.Adapters.Refit` — only the latter references Refit). `IWarpAdapters.BeginCall(adapter, operation, group?)` → `AdapterCallScope`. **Identity axes:** adapter = policy + health boundary; group = runtime who/where (explicit, never heuristic); operation = what (bounded, may be heuristic). Litmus: changes request *structure* → operation; changes only *destination/on whose behalf* → group. `opt.AddAdapters()` gates DB recording only. Caps: `MaxDistinctOperations` 50 and `MaxDistinctGroups` 500 collapse heuristic names to `{other}` (explicit names never collapse); `IncludeGroupInMetrics` default false. **Shared rate limit:** same name = shared limit; persisted policy is **first-writer-wins** (later mismatches enforce the persisted one, warn, `HasPolicyConflict`); precedence `RateLimitOverride` row > persisted > local code — change a limit via an override row, not a redeploy. `Respond429` returns a synthetic `WarpThrottledResponse`, synthesised in the OUTERMOST `WarpAdapterHandler` and recognised by TYPE (a real vendor 429 stays `Failed`). No retry dependency in the HTTP binding (resilience is a user handler). Enums from 1.
- **§8.20** **Outbound webhooks** are Core (`Warp.Core.Webhooks`) and always-on — no `AddWebhooks` gate (`opt.AddWebhooks` is optional config: custom signer, exhausted handler, `PublicAddressesOnly`, `TrackEndpointHealth`, `DeduplicateByEventId`, endpoint health handler); any `AddWarpServer` worker drains queue `warp:webhooks`. **Boundary:** host owns subscriptions, fan-out, payloads, endpoint enable/disable, secrets; Warp owns everything after `IWebhookDispatcher.SendAsync` (persists `Pending` + first attempt in the caller's transaction, returns delivery id). **The delivery row is the state machine** (`WebhookDeliveryStatus {Pending, Delivered, Exhausted, Parked, Cancelled}`); the executor job `ExecuteWebhookDelivery` always completes. Rows are **self-contained** (URL, headers, payload, schedule, signing, secret stamped at send). Attempts are adapter calls on `warp-webhooks` (no attempt table; per-attempt rows need `AddAdapters()`). Retries = fresh `Scheduled` jobs; `(RetrySchedule, AttemptCount)` is the plan (`null` = `[1m,10m,1h,6h]`, `[]` = single attempt); no app-level schedule knob. Signing `None`/`StandardWebhooks`/`Custom` (custom without a signer throws at `AddWebhooks`). Secrets/`Authorization` headers redacted on every read surface. Exhaustion handler: at-least-once, post-commit, never propagates. **Attempt bounds (8.1):** send with `ResponseHeadersRead`, read at most the capture cap (nothing when capture is off), never drain; `WarpConfiguration.WebhookAttemptTimeout` (30 s) is a linked token around send + capture read — **never set `client.Timeout`** (the host may own the `warp-webhooks` client); a timeout before the headers is a failed attempt, a timeout during the capture read only abandons the capture (the status already decided — never turn a 2xx into a retry); job-token cancellation is logged distinctly; minimum 1 ms. **`PublicAddressesOnly`** (ON by default since 8.1, in every process via `AddWarp` — `WebhookAddressPolicy`; only an explicit `AddWebhooks(w => w.PublicAddressesOnly = false)` turns it off, a later call that does not set it never undoes that; per PROCESS: guards the attempts this process runs; with it on `SendAsync` also throws `ArgumentException` for non-public IP literals and `localhost`; `WarpTestServer` and the demos opt out because they stub the client / post to localhost): a `PostConfigure` builder action (`WebhookHttpClientSetup`) sets `ConnectCallback = WebhookAddressGuard.ConnectAsync` on a `SocketsHttpHandler` (resolve → keep `IsPublic` → connect to exactly those; no DNS-rebinding gap; other host settings kept); any other primary handler is KEPT, never replaced (a host proxy/mTLS handler must not be dropped), behind `WebhookGuardUnavailableHandler`, which FAILS EVERY ATTEMPT CLOSED with the fix in the message, logged once at Warning (`WebhookGuardUnavailableWarning`, triggered at startup by `WebhookClientStartupCheck` in `StartedAsync`, servers with a worker only, which must NEVER fail startup) — never send unguarded; refusal = `WebhookAddressNotPublicException`, message names the host, never the addresses; with a proxy the proxy is checked. **Webhook worker group (8.1):** `WebhookWorkerCount` (default 4) adds a dedicated group polling only `warp:webhooks` and the default group stops polling it, so slow receivers cannot starve job workers (worker hot path untouched — configuration only, `GetEffectiveWorkerGroups`); `0` = old shared shape; explicit routing (`Queues` or an `AddWorkerGroup` group listing it) wins and adds no group; the dedicated group is not counted by the zero-job-worker validation (`TotalWorkerCount`). Tests that pin one group / one dispatcher set `WebhookWorkerCount = 0`. **Redirects off (8.1):** Core's default primary handler is `SocketsHttpHandler { AllowAutoRedirect = false }`, installed by a builder action INSERTED AT INDEX 0 so any host primary handler (either registration order) replaces it with its own redirect choice and a host `UseSocketsHttpHandler` reuses it. **Redeliver with a rotated secret:** `Redeliver(id, WebhookRedeliveryOptions, ct)` is a default interface member (forwards without a secret, throws `NotSupportedException` with one) — never add a parameter to the original; the secret is written in the SAME guarded `ExecuteUpdate` as the settled→Pending flip and validated like `WebhookSend.Secret` first. **Endpoint health (8.1, opt-in, STAMPED on the row at send — `TrackEndpointHealth`, only with a `GroupName`):** endpoint = `GroupName`, never URL; state in `WebhookEndpoint` (PK `Name`, `WebhookEndpointState {Healthy, Failing}`), row created by the executor in its OWN scope before the outcome transaction (a duplicate-key race there would abort the outcome tx on PostgreSQL). In the outcome transaction: a tracked final failure PARKS the delivery (no job, no exhausted callback) — including the one that flips Healthy→Failing, whose `WebhookEndpointFailing` signal is the alert; no endpoint row ⇒ `Exhausted` (never park what nothing releases); a success flips Failing→Healthy. `WebhookEndpointMonitor` (`IServerTask`, job-only, server context, stages jobs via `WebhookExecutorJobs`) releases parked of Healthy groups oldest first (≤200/run, `RerunImmediately` while full, fresh budget), probes due Failing groups (oldest parked, `AttemptCount = RetrySchedule.Count` ⇒ one attempt; failure re-parks), raises still-failing once per period; all signals post-commit (§8.25) to `IWebhookEndpointHealthHandler` + `WebhookEndpoint*` events. Retention sweeps skip `Parked`. **Outcome commit is guarded on `Status == Pending`** (an `ExecuteUpdate` that also stamps `LastAttemptAt`/`LastStatusCode`/`LastFailureReason`, #357) — a delivery `Cancel`led mid-attempt is never overwritten and schedules no retry; `Cancel`/`CancelGroup` flip Pending|Parked→Cancelled in one guarded statement. New `IWebhookCommandService` members (`Cancel`, `CancelGroup`, `ProbeEndpoint`) are default interface members that throw `NotSupportedException`. **Dedupe** (opt-in): `DedupeKey` = SHA-256(length-prefixed event id + URL), unique index (nullable: SQL Server filters non-null by convention, PostgreSQL nulls distinct); read-before-insert, concurrent duplicates lose on the index. SLO kind `WebhookDeliveryLatency` (§8.31) counts delivery rows. Guards: `WebhookEndpointHealthTestsBase`, `WebhookCancelDedupeTestsBase`, `WebhookEndpointHealthRouteTestsBase`, `WebhookEndpointHealthUnitTests`, `WebhookDeliveryLatencySloTestsBase`, `WebhookAttemptLimitsTestsBase`, `WebhookAddressGuardTests`, `WebhookHttpClientHandlerTests`, `WebhookRedirectTestsBase`, `WebhookWorkerIsolationTestsBase`, `WebhookQueueWiringTests`, `WebhookRedeliverSecretTestsBase`, `WebhookRedeliveryOptionsDefaultTests`. **Stuck-delivery sweep** in `StaleJobRecovery` runs on the SERVER context and stages the executor job directly (`JobHelper.CreateJob` + `CapturePending` → `OnCommittedAsync`), stamping `CanBeRestarted = true` — never through the `TContext`-bound `IPublisher`/`IWebhookRedeliveryEnqueuer` (self-blocks on SQL Server without RCSI).
- **§8.21** **Inbound endpoint observability** (`Warp.Http.Observability`; `opt.AddEndpointObservability(...)` + `app.UseWarpHttpObservability()` after `UseRouting`). Observes Warp endpoints plus host endpoints opted in via `WithWarpObservability()` / `[WarpObserved]`; `ExcludeFromWarpObservabilityAttribute` always wins (stamped on every dashboard endpoint). One identity builder, `WarpEndpointIdentityFactory`: **identity = method + route TEMPLATE** (rendered from `RoutePattern`, constraints normalized away, never the request path). Counter dimensions Total + Group only; `GroupSelector` must be low-cardinality (never IP/user id). Outcome `Failed` = final wire status ≥ 500 or exception after response start; an exception before response start defers recording to `Response.OnCompleted`. 4xx count as Success. `RecordCalls = FailuresOnly` skips success rows only. Caller IP / user-agent / user name are captured by default and are PII. Retention global (`EndpointCallLogRetention` + `...RetentionCount`). Guards: `HostEndpointObservabilityTestsBase`, `WarpEndpointIdentityFactoryTests`.
- **§8.22** **Log retention is age + count** for adapter call logs, webhook deliveries, endpoint call logs (and client events, app-instance logs): `*Retention` `TimeSpan` + `*RetentionCount` `int?` (null = off), whichever trims first, batched + `MaxSweepBatchesPerTick`-capped in `ExpirationCleanup`. Adapters also take a per-adapter `CallLogRetentionCount` persisted on `AdapterDefinition`. Webhook count-trim excludes `Pending`. Average latency is backed by a `dur` duration-sum counter so aggregates outlive the sweeps.
- **§8.23** **Multi-application observability** — for a shared database; NOT isolation (that is a separate `opt.Schema`). **`ApplicationName` null ⇒ byte-for-byte old behaviour.** Every server is an instance (`Server.Application/Version/Environment` stamped by `Heartbeat`); a non-server process writes one `ApplicationInstance` row via `ApplicationHeartbeatHost` (only when `ApplicationName` set). Lifecycle in `ApplicationInstanceLog` (`ApplicationInstanceEventType` from 1). **Provenance ≠ execution:** `Job.Application` = publisher (preserved on requeue, filter only); execution metrics are attributed to the EXECUTOR app; no per-creator job metrics. Unified roster `InstanceView`; Applications page replaces Servers. **Deploys:** `ApplicationDeploy` recorded only at registration (never per heartbeat), gated on name + non-blank version; unique index `(Application, Environment, Version)` with `Environment` stored non-null (`""` = none); race resolved by probe → insert → on conflict clear tracker + re-probe; best effort. `ApplicationDeployRetention` never deletes the newest per (app, env). `IApplicationDeployQueryService` is a separate interface (do not add members to the `TryAdd`-registered `IApplicationQueryService`). **Verdict** (`GET .../applications/verdict`, `DeployVerdictService`): composes existing reads, adds no query; window = complete fine buckets strictly after the deploy; latest deploy `pending` until ≥ `minWindow`; superseded deploy never waits; any Breaching ⇒ fail (never downgraded by coverage); Acknowledged never fails; without `board` counts every board's tiles + one `GetObjectives`; with `board` only that board's tiles/SLO tiles (unknown name → 404; `Default` resolves to the `IsDefault` board). SLO check `value`/`target` share one scale (`DeployVerdictMath.SloTarget`). Guards: `ApplicationDeployTestsBase`, `DeployVerdictTestsBase`, `DeployVerdictMathTests`.
- **§8.24** **Observability sinks** — `RecordingSink { Database=1, Otel=2, Both=3 }`, default `Database`. Per surface (`AddAdapters(o => o.Sink)`, `AddEndpointObservability(o => o.Sink)`, `WarpConfiguration.JobMetricsSink`). `Otel` wires **no recorder, no flusher** (no rows, no per-app counters) and instead enriches the span Warp already emits, only when `Activity.IsAllDataRequested`. **No OTel-log recorder** — routing payloads through `ILogger` leaks to every log provider; do not reintroduce. Repeated `AddAdapters` calls merge into one options bag and the explicit `Sink` wins in either order (`RecordingSinkWiringTests`). `IAdapterCallRecorder` stays internal. Control-plane state (jobs, servers, sagas, webhooks, roster) always stays in the DB. Meter tags low-cardinality only; `group` stays off meters.
- **§8.26** **Queue metrics** (always-on). **Queue-wait** = `max(0, claimTime − ScheduleTime)` at the worker claim site, staged on the worker and handed to `WarpCounterBuffer` after the claim commits (no row, no query); keys `QueueWaitKeys` (`qwait`, per-app `qwait-app` without histogram). **Backlog** depth + oldest age sampled off the hot path by `BacklogSampler` (`IServerTask`, one grouped EF query on the existing claim index); writes gauges + overwritten `qbacklog:` `Statistic`s (not `Counter`). **Backlog is queue-global, never app-sliced.** Both respect `JobMetricsSink`. `GET .../queues/metrics` is public API but the dashboard reads the `queues` counter family (percentiles list incl. p99) — **do not reintroduce the Queues page**.
- **§8.27** **Client (frontend) observability** — public ingest endpoint (`MapWarpClientObservability()`, `Warp.Http.ClientObservability`; pipeline in `Warp.Core.ClientObservability`). One `ClientEvent` row discriminated by `ClientEventType {Error, Vital, Log, Event, Request}`. **Hostile input:** auth by write-only DSN key → trusted app name (unknown → 401), CORS origin allowlist (same-origin bypasses), in-memory per-IP rate limit checked BEFORE the body read (never DB-backed), hard size/batch caps, unknown types dropped-and-counted. Names and log levels collapse beyond per-type caps; **vital names go through the fixed `KnownVitals` allowlist** for counter keys and meter tags. Vitals report **p75** (Google). Two-tier storage: raw rows (age 7 d + count 100k/app) + durable `clientevent` counters. IP off by default; consent is the host's job. Correlation: `traceparent` + `baggage: session.id` → `EndpointCallLog.Session`; **jobs are not stamped with session** (trace id links them).
- **§8.28** **Unified trace view** (`ITraceQueryService.GetTrace`, `GET .../traces/{traceId}`) unions EXISTING rows on trace id — `Job`, `EndpointCallLog`, `AdapterCallLog` (string `"N"` trace id), `ClientEventLog` of type Request. **No `Span` table, no `ActivityListener` collector, no hot-path span capture — do not reintroduce.** Job timing comes from the latest terminal `JobLog` with `DurationMs` (two-step fetch, §5.2); falls back to a `CreateTime` marker. Read-only, no schema.
- **§8.29** **Error grouping / Issues** (always-on; `ErrorGroupingInterval = null` disables). Sources append an `ErrorOccurrence` **inbox row** — jobs in the existing finalization save (both worker modes; it stays a ROW because it must survive the process), endpoint/adapter/client in their flushers. `ErrorGroupAggregator` (`IServerTask`) drains-and-deletes, fingerprints off the hot path, upserts `ErrorGroup`, folds `errorgroup` counters. Fingerprint (`ErrorFingerprint`) = hash(source + exception type + locus); message normalized OUT of identity and is the PII-safe title; stack sources use the top in-app frame (`InAppNamespaceDenylist`); unwraps `TargetInvocationException`/`AggregateException`. Counted: jobs every caught exception (retries too); endpoints 5xx + 4xx (4xx default-filtered, off the SLI); adapters `Failed` only; client `Error` only. Lifecycle `Unresolved/Resolved/Ignored`: a Resolved group reopens only on an occurrence after `StatusChangedAt` and fires `IssueRegressed` from `OnCommittedAsync`; Ignored never reopens. `MaxDistinctErrorGroups` 2000 → `{other}`. Otel-only sources produce no issues.
- **§8.30** **Metrics retention tiers** — fine (5 min) → hourly → daily via an explicit suffix `MetricTiers` (`:{m5|h1|d1}:{stamp}`); never infer resolution from stamp shape. `jobstat`/`qwait` emit fine (+ tiered `pcth`); others emit unmarked hourly (treated as legacy hourly). Lifetime totals and lifetime `pct` untouched. `StatisticRollup` (`IServerTask`) is family-agnostic, sums-then-deletes, is the **only** pruner of time-bucketed rows, and is capped (§6.2.1). All history readers are tier-aware and down-bin to the hour. Config: `FineResolutionMinutes` (≥ 1, ordering fine < hourly < daily validated in `AddWarpServer`), `FineResolutionRetention`, `HourlyStatisticsRetention`, `DailyStatisticsRetention`, `StatisticRollupInterval`. No schema change.
- **§8.31** **SLO / error budget** — opt-in `opt.AddSlo(...)` (repeat calls merge). Seeder is insert-if-absent (DB wins), runs under transaction lock `warp:slo-seed`, matches **in memory** (names OrdinalIgnoreCase, other fields Ordinal — never SQL collation), only against rows stored before the pass. `Upsert` of a missing `Id > 0` returns 0 (404), `Id ≤ 0` inserts with key reset. `SloValidation` is shared by route and seeder and clears columns that don't belong to the kind. `SloEvaluation` PK is `ValueGeneratedNever()`. `SloEvaluator` (`IServerTask`, every server) uses pure `SloMath`; **zero observations ⇒ `NoData`, never Healthy**; **`SloMath.IsNoData` is checked BEFORE `Classify` — never reorder** (`Classify(NaN)` reads Healthy). Fast-burn short window = window/12, ≥ 5 min, read from the fine tier; latency kinds read tiered `pcth`. Deadline miss is decided at finalization (any terminal state past `TimeoutDeadlineUtc`, or ended by the timeout itself). Breach edge fires `SloBreached` once, ack-suppressed, from `OnCommittedAsync`. **`WebhookDeliveryLatency` (12, 8.1)**: share of a group's (`*` = all) deliveries delivered within `TargetValue` minutes (`Percentile` = required share, default 95), counted from `WebhookDelivery` rows (`LastAttemptAt − CreatedAt`), only rows at least `TargetValue` old, `Cancelled` excluded; NoData with none. **Metric kinds 6–11** (`MetricRatio`/`MetricThreshold`/`MetricVolumeFloor`/`MetricGap`/`MetricLatency`/`MetricGaugeThreshold`): `Dimension` = instrument name, one `MetricFilter` grammar; `SloValidation.AcceptsInstrument` (latency ⇒ histogram only, gauge-threshold ⇒ gauge only, 6–9 ⇒ not a gauge); a mismatch, unknown instrument or corrupt definition ⇒ Error log + NoData. `MetricLatency` is a good-event ratio split on the bucket ladder; `MetricGaugeThreshold` weights buckets by time covered. Window ≥ 600 s. Annotations are display-only. Detail in the design note.
- **§8.32** **Dropped-record visibility** — every drop site calls `DroppedRecordCounters.Track(DropPipeline, n)` (one interlocked add) besides the OTel meter; per-process `DroppedRecordReporter` (`BackgroundService`, not a locked task; no DB work when nothing dropped) folds to `warpsys:records-dropped:{pipeline}` and raises a throttled `RecordsDropped` notification post-commit. Dashboard "Dropped (24h)" tile.
- **§8.34** **Custom application metrics** — Warp is a **collector** of `System.Diagnostics.Metrics` (host code takes no Warp dependency); opt-in `opt.AddMetrics(...)` (merges on repeat). Detail is large: **read `.claude/references/design-notes/8.34-custom-metrics.md` before changing metrics, boards, annotations or chart/SLO tiles.** Invariants:
  - **Collector** (`WarpMeterCollector`): exact meter names only, **never the `Warp` meter**; callback in-memory only, never throws, non-finite dropped. Histogram bounds precedence config > advice > unit default, ≤ 20, CSV ≤ 256 chars — **throw, never truncate**; rows with different bounds never merge.
  - **Series** = (instrument, application, canonical sorted tag set [, version only with `ByVersion()`]). Tag values truncated to 64 — a size control, **not** privacy: tag values must never carry PAN/PII/customer ids. Caps per process (`MaxTagsPerInstrument` 6, `MaxValuesPerTag` 100, `MaxSeriesPerInstrument` 500, `MaxInstruments` 300) → `{other}`; **a report never includes a tag value**.
  - **Flush**: `MetricFlusher` is a per-process `BackgroundService` (not a locked task), writes partial fine `metric_point` rows, merges back on failure; registry upserted in a separate save. Server hosts replace the sink with `ServerMetricPointSink`.
  - **Rollup** (`MetricRollup`, `IServerTask` in `AddServerHostCore`): compact → fine→hourly → hourly→daily → prune, sharing the `MaxMetricRollupRowsPerTick` cap (never remove); parents saved before sources deleted **by the ids actually summed, never by predicate**; keys matched in memory, ordinal.
  - **Reads** sum on read across EVERY tier overlapping the range; the still-filling bucket is `Incomplete` and excluded from headlines. One `MetricFilter` matcher shared by page, SLOs and board. The `{version}` pseudo-tag is rejected in stored SLO/board filters. **Units are displayed only through `src/ui/src/lib/metricUnit.ts`** — never print `instrument.unit` raw.
  - **Boards** (`MetricBoard`, `MetricBoardTile`): tile kinds Value/Ratio/Chart/Slo; validation shared via `MetricBoardValidation`; `MaxTiles` 48 per board, `MaxChartTiles` 12, `MaxBoards` 100. Every board/tile write and the seeder run under transaction lock `warp:metric-board` (timeout → 503). Default board = `IsDefault`, created once, renamable, never deletable; Default's tiles stored with `BoardId = null`. Names unique ignoring case, enforced in memory. Seeder matches by `SeedKey` then name, never the Default board for a named seed. Tile edit with omitted `boardId` keeps its board. Board window cut at the fine bucket (`CompleteUntil`); batched read stays flat in tile count. SLO delete cascades its tiles + annotations under the board lock.
  - **Annotations** (`MetricAnnotation`): note text + author only (author from the authenticated principal, never the body; text never logged); kept forever; **acknowledged noise requires a COVERING note active at window end** (overlap only decides display).

## Outbound Adapters — architecture (moved from `architecture.md`)

- **§2.15** Outbound service-call observability mirrors inbound `Warp.Http`. Core: `IWarpAdapters.BeginCall(adapter, operation, group?)` → `AdapterCallScope`. **Telemetry is unconditional** (Activity `{adapter}.{operation}` + `warp.adapter.calls`/`duration`); **only DB recording is gated by `opt.AddAdapters()`** (`DbAdapterCallRecorder` + `AdapterCallFlusher`). Recording is **lossy by design** — a full channel drops the record and increments `warp.adapter.records_dropped`; user calls are never blocked. Entities `AdapterDefinition`/`AdapterCallLog` are always in the schema (§2.11). Stats write `Counter` rows (§6.2). `IAdapterQueryService` is registered by `AddWarp`. The cluster-shared rate limiter reuses `RateLimitBucket` (key `warp:adapter:{name}`); shared policy is **first-writer-wins** — precedence `RateLimitOverride` admin row > persisted definition > local code; change a shared limit via an override row or by clearing the persisted policy, not by redeploying. `Warp.Adapters.Http` has no retry dependency (resilience is a user handler via `ConfigureHttpClientBuilder`); `Warp.Adapters.Refit` is the only package referencing Refit. Both compose against Core's public API only (§0.5). See `website/docs/features/adapters.md`.
