# Addons & features (§8.8–§8.10, §8.17, §8.18)

> Loaded only when touching the paths above. Rules only — rationale, history, measurements and full rot-guard lists live in `.claude/references/design-notes/<section>-*.md`; **read the note before changing a section's area**.

## Rate limiting, policies, recurring jobs

- **§8.8** **Rate limiting** is opt-in via `opt.AddRateLimit()`. Styles (`Style`, from 1): `Fixed` (wall-clock window, floor-aligned to UTC), `Sliding` (last N starts), `TokenBucket` (paces at `count/perSeconds`, burst `count`). Modes: `Skip` (default → `Deleted`) and `Wait` (rescheduled via `JobOutcome.RescheduledState`). `perSeconds` ≤ `MaxWindowSeconds` (7 d). Live state in `RateLimitBucket`; the lock is released after check-and-increment, never held during the handler. Wait-mode reschedules land in `Scheduled`, so release cadence is floored at `ScheduledActivationInterval` (DB push does not accelerate them). **Ordering: `AddConcurrency()` before `AddRateLimit()`.**
  - **Policy resolution (all policy attributes — `[RateLimit]`/`[Mutex]`/`[Semaphore]`/`[Timeout]`/`[Retry]`/`[CircuitBreaker]`):** legal on the contract, the handler class, or both. Resolved in ONE place, `PolicyResolver`, at execution. Rungs, rung-major: explicit metadata on the row → handler class → contract → global options. **The winner is stamped into job metadata and never re-resolved** (persisted by the finalizing write — all three arms: success, failure, graceful cancel — in BOTH worker modes). Stamp-once is per family, not per job. Global defaults are NOT stamped.
  - **Publish stamps nothing except `Timeout(Scope = Total)`** (contract-only; `Scope = Total` on a handler is `WARP002` at build, inert + logged once at runtime). Do not reintroduce publish-time stamping behaviours.
  - Retry is atomic per rung: `MaxRetries` and `RetryDelays` come from the same rung; either explicit field claims the rung. Concurrency/RateLimit key on `ConcurrencyKey`/`RateLimitKey` alone and stamp all-or-nothing.
  - `PolicyResolver.Bypasses` lets through non-job shapes, `JobId == Guid.Empty`, and `IPolicyExemptHandler` (saga proxies). Self-handling jobs are exempt.
  - A cancelled attempt is not a spent retry: `RetryPipelineBehavior` rethrows a cancelled-token `OperationCanceledException` before retry bookkeeping.
  - `CircuitBreaker` is resolved but never stamped (group state is a DB row). A routed message child's default breaker group is its handler type.
  - **Trap:** `IJobContext.GetMetadata<T>()` copies the dictionary — never cache the proxy across `next()`; re-read after it.
  - No startup validation of policy attributes; build-time only `WARP001` (policy on stream/in-memory handler) and `WARP002`. Messages behave exactly like jobs (router copies only explicit metadata). Skip-mode deletion of a routed child counts as settled for parent finalization.
- **§8.8.1** **Refusal fast paths must be EXACT** — they may only refuse what the database would refuse. `RateLimitGate` (per-key reopening instant; keyed by the job's declared count/window/style; admin override changes bounded by `MaxClosedAge` 5 s and invalidated locally by `RateLimitManager`) and `ConcurrencyLocalHolds` (keyed per **(lock name, limit)**, never name alone). Wait mode takes per-job slots from the cluster cursor `RateLimitBucket.NextSlotUtc` (leases ≤ `MaxLeaseSize` 20 and ≤ `LeaseHorizon` 5 s) — **never reintroduce a shared reschedule time**. Windows shorter than `ScheduledActivationInterval` step by the activation interval (`IScheduledActivationCadence`). Release order: decrement the local hold BEFORE releasing the DB lock. Mutex Wait requeues with `ScheduleTime = now` (no backoff). The rate-limit lock is released BEFORE the handler runs. Public behaviour ctors build private instances; only internal DI shims share the singletons. **A host-registered `IRateLimitManager`/`IConcurrencyLimitManager` decides the job's limit** (#349): `ReplacedRegistration` reads the LAST service descriptor once, lazily — if it is not Warp's own implementation the resolver reads through the manager (resolved only when a job has a key); otherwise it reads the table on `DeferredWarpContext` and never builds the manager (it would build `TContext`, §6.17). Guard: `LimitManagerReplacementTests`. Guards: `RateLimitGateTests`, `ConcurrencyLocalHoldsTests`, `AdmittedJob_LockReleasedBeforeHandlerRuns`, `SemaphoreSlotsHeldByThisProcess_MutexOnSameKey_StillAcquires`.
- **§8.9** **Recurring jobs.** `RecurringJobScheduler` creates jobs with `ScheduleTime = now`; `AddOrUpdateRecurringJob` only registers/updates the definition (saves under its own distributed lock — deliberate §5.8 exception). A firing is an enqueue site: capture `NotificationDispatch.CapturePending` before `SaveChanges`, dispatch from `OnCommittedAsync`. Disabled definitions are visited and write a `Skipped` `RecurringJobLog` with no `Job`; the skip advances `NextExecution` but **must not advance `LastExecution`**. `TriggerRecurringJob` ignores `DisabledAt`. Every single-definition `IRecurringJobService` method keys on the **name** (normalized by `RecurringJobName.Normalize`: trim, non-empty, ≤ 200), never the surrogate `Id`; unknown name → `ArgumentException` for commands, not-found for queries. Dashboard `{prefix}/api/recurring/{id}` where `{id}` = `UrlSafeId` of the name; bad id → 404. `ExpirationCleanup` stamps `RecurringJobLog.FinalState` immediately before deleting a job **in both delete paths** (age and count) — a new delete path must do the same. Retains last 100 logs per recurring job.

## Source generators

- **§8.10** **Source generators** (`Warp.SourceGenerator`, `Warp.Http.SourceGenerator`) target `netstandard2.0`. The worker runs jobs/messages through the generated dispatch (`GeneratedJobDispatcher` per assembly → `WarpGeneratedHandlerRegistry.AddJobDispatch`, first registration wins), with the reflection path as fallback for types no generator saw. **Keep generated dispatch out of failed jobs' stack traces:** per-type `Execute_*` methods are not `async`, `Task` → `Task<Unit>` through the one `AsUnit` helper, class emitted under `#line hidden` (`[StackTraceHidden]` does not work). `[WarpHttpGet/Post/Put/Patch/Delete]` emit `RequestDelegate`s; `IJob`/`IMessage` rejected (`WHTTP001`). A handler returning `IResult` owns the HTTP response. Form members (`IFormFile`/`IFormFileCollection`/`IFormCollection`/`[FromForm]`) bind from the form; form + JSON `[FromBody]` is `WHTTP006`. **`WARP003`** (contract nothing handles) is a warning; projects with no job-family handler, saga messages (`ISagaHandler<,>`), self-handling jobs, open generics and referenced contracts are exempt; `IRequest`/`IStreamRequest` are out of scope. Guards: `GeneratedJobDispatchTests`, `UnhandledJobDiagnosticTests`.

## Sagas & background services

- **§8.17** **Sagas** (opt-in `opt.AddSagas()`, `Warp.Core.Sagas`): subclass `Saga`/`Saga<TKey>` (`string`/`Guid`/`int`/`long`), `[Correlate]` property, `[StartsSaga]` messages, `ISagaHandler<TSaga, TMessage>` registered via `services.AddSagaHandler<H>()`. Storage `SagaState` + `SagaJobLink` (FK cascade). **Delete-on-completion** (`MarkCompleted()` removes the row in the same save). No auto-expiry; `ITimeoutMessage` self-schedules, and timeout-after-completion drops (`Deleted`). The proxy serializes per key on `warp:saga:{TSaga.FullName}:{key}` via `IWarpSemaphoreProvider`; optimistic `Version` is defence in depth; busy/conflict requeues use 50–250 ms jitter. Keys trimmed, non-default, ≤ 200. `SagaPiiCheck` rejects PII-named `[Correlate]` properties (opt out with `IsAnonymized = true`). `ISagaCommandService.ForceComplete` takes the saga mutex and audits. See `website/docs/features/sagas.md`.
- **§8.18** **`WarpBackgroundService`** is base Warp (`Warp.Core.BackgroundServices`, no opt-in); topology is §2.13. Users register via `opt.AddBackgroundService<T>()`. `Scope`: `PerServer = 1` (default) or `Singleton = 2` (cluster lease, 30 s TTL renewed in `Heartbeat`; lease deleted in `StopAsync` before waiting on user code). Entities `BackgroundServiceDefinition`/`Instance`/`Lease`/`Log` in `Warp.Core.Data.Entities`; orphaned definitions removed by `ExpirationCleanup` after `BackgroundServiceDefinitionOrphanGrace` (2 min). **Captive dependency foot-gun:** subclasses are singletons — inject `IServiceScopeFactory`, not `DbContext`. Log capture is auto-wired (`MinLogLevel` Information, 100/s, 4 KB truncation, 1000-row/7-day retention); §1.2 applies to log output. `AddWarpWorker`/`WarpWorkerConfiguration`/`WarpWorkerBuilder` were removed in 2.0. See `website/docs/features/background-services.md`.
