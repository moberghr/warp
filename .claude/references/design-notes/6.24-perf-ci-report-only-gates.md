# §6.24 — design notes (perf-CI gates and their calibration)

> Full rationale, measurements and rot guards behind the condensed rule §6.24 in `.claude/rules/performance-worker.md`. Read on demand when changing this area. The file name is historical: until #363 these gates were report-only pending calibration.

**§6.24** **Perf-CI gates, calibrated by three no-op runs.** The gate decision lives in `PerfGates` (`src/benchmarks/Warp.ServerBenchmarks/Lab/PerfGates.cs`): the limits, which rows are report-only (`IsReportOnly`), the lines a head row crossed (`Breaches`) and how a lopsided two-server case is judged (`LopsidedSides`, `LopsidedFails`). `PerfCompare.RenderScenario` only formats what it returns. The file has no dependencies and is compiled into `Warp.Tests` (`<Compile Include ... Link>`; the benchmarks executable cannot be referenced: it pins its own Testcontainers), where `PerfGatesTests` (NoDb) guards every limit.

## Calibration (#363)

Three runs of the Performance workflow with main as both base and head (runs 46080133283, 46080140651, 46080148230; PostgreSQL 17 and 18, SQL Server 2022 and 2025), plus an earlier one for rate limit. The worst head-vs-base change on identical code, per metric:

| Metric | PostgreSQL, draining | PostgreSQL, idle (per second) | SQL Server | Gate |
|---|---|---|---|---|
| Statements/job | ≤ 2% nearly everywhere; Rate limit +4.6% (+5.3% earlier); TwoServersUnderLoad, RecurringJobs, BackgroundLoad < 3% | −10.8% / +1.3% | up to ±37% | PG +5%, Rate limit +8% |
| Commands/job | +7.4% (Long-running), +5.8% (Rate limit), otherwise < 5% | −9.2% | up to ±17% | PG +10% |
| WAL/job | ≤ 3% on every draining scenario | +6.3% / −13.9% | — | PG draining +6% |
| Buffers/job | up to +31% (Retries), −57% | +69% | up to 761% | PG ×5 blow-up (unchanged) |
| Jobs/s | 0.70× – 1.47× | — | up to ±58% | PG collapse to a third (unchanged, not on clock-bound) |
| Xacts/job | up to 156% | up to 17% | up to 274% | reported |
| DB ms/job | up to 43% | — | up to 285% | reported |
| Allocated | up to 26% | — | up to 16% | reported |
| Two-server smaller share | 47–50% always | — | 12–40% (run 1 failed on it) | PG fails under 20%; SQL Server warns |

The idle scenarios (Idle server, Idle cluster) swing 10–27% on everything, so every metric of theirs is report-only. Every SQL Server row is report-only: its statements and buffers come from Query Store (measurement version 2), and their noise is many times any line worth having. Replaying the three runs through the new gates: all 114 comparisons pass.

**Rate limit's +8%** is a per-scenario line (`[CiScenario(StatementTolerancePct = 8.0)]` on `RateLimitBenchmark`). Its statements per job move about 5% between identical builds where every other draining scenario moves under 2%; the cause is not known. **Follow-up:** find that variance, then drop the override back to the default.

## Shapes to keep

- **Report-only rows** show their lines and mark a crossed one ⚠️ "(report-only)"; they fail nothing. `[CiScenario(Calibrated = false)]` stays for a new or reworked scenario until three no-op runs have measured it; no scenario carries it today.
- **Validity checks fail whatever the calibration**: a measurement missing on one side (statements; WAL and commands on PostgreSQL draining rows), statements missing on both with the database configured, per-job against per-second, and on PostgreSQL a two-server case where one server completed under 20% of the jobs. On SQL Server that last one is a ⚠️ warning appended to the Gate cell, because the split there is that uneven between identical builds.
- **Lines sit clear of the measured noise, not at it.** A gate that fires on drift gets ignored, then switched off. The regressions this suite was built after were far past every line (+48.6% statements for the claim predicate, 18× buffers for a plan flip). Do not tighten a line or add a metric without new no-op runs, and never raise a line to get a change through.
- **DB time stays reported**: a provisional +25% PostgreSQL line once failed message routing on a swing it shows between identical builds (~60%).
