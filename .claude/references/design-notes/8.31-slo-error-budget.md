# §8.31 — design notes (slo error budget)

> Full rationale, history, measurements and rot guards behind the condensed rule §8.31 in `.claude/rules/`. Read on demand when changing this area. Verbatim from the pre-split `project-specific.md` (2026-11-24).

**§8.31** **SLO / error budget** turns Warp's durable aggregates into objectives with error-budget + multi-window burn-rate alerting. **Opt-in** `opt.AddSlo(o => o.AddObjective(...))` (registers `ISloMarker` for the dashboard `slo` flag + an insert-if-absent config seeder — DB wins, never clobbers a dashboard edit; a seed failure logs **Error**, not a swallowed Warning, since the schema is migrator-gated present; the checks + inserts run under the transaction-scoped lock `warp:slo-seed` (`TransactionLock.RunAsync` — a TRY lock retried until the holder commits, 30 s cap; no lock in a provider-less host) so N replicas seed one copy; a seed skipped because a stored row shares its NAME but differs in fields logs **Information** with the differing field NAMES only (§1.2, never values); repeated `AddSlo` calls MERGE into one `SloOptions` (one seeder, like `AddMetricBoard`/`AddMetrics`), so the duplicate-name check spans every call; config names are unique per kind + application **OrdinalIgnoreCase** at registration, the same comparer the seeder matches names with; the seeder loads the candidate rows once (by the seeds' kinds) and matches **in memory** — names OrdinalIgnoreCase, fields (dimension, application, filters, tags) Ordinal — never in SQL, where the collation would decide (SQL Server case-insensitive, PostgreSQL not); `Upsert` of an Id that no longer exists returns 0 → route 404 `{ error }`, never re-creates; an Id ≤ 0 is an insert with the key reset to 0, never the caller's key — SQL Server refuses an explicit identity value). **Boundary validation** (`SloValidation`, shared by the upsert endpoint → 400 and the seeder/`AddObjective` → throw): Kind in range, positive window, rate target in (0,1), threshold target > 0, latency percentile 1–99 defaulted to 95, percentile cleared for non-latency kinds, and EVERY metric-only column (`TagFilter`/`SecondaryMetric`/`SecondaryTagFilter`/`RatioTag`/`GoodValues`/`BadValues`/`BaselineDays`/`Comparison`/`GaugeAggregate`) cleared for kinds 1–5 — a malformed objective can't silently pin itself Healthy (window≤0) or Breaching (rate target>1). **Entities** (always-in-schema §2.11, mirrored §2.14): `SloDefinition` (`SloKind` {SuccessRate=1, QueueWaitLatency=2, ExecutionLatency=3, BacklogDepth=4, DeadlineAttainment=5}, Dimension=job-type/queue/`*`, Application?, TargetValue, Percentile?, WindowSeconds, Enabled; enums from 1 §8.11) + `SloEvaluation` (1:1, PK=`SloDefinitionId` — **`ValueGeneratedNever()`**: a caller-supplied FK-as-PK, not an IDENTITY, or SqlServer rejects the explicit insert while Postgres tolerates it; Attainment, BudgetRemaining, BurnRateShort/Long, `SloState` {Healthy=1, Warning=2, Breaching=3, Acknowledged=4, **NoData=5**}, AcknowledgedUntil?, LastEvaluatedAt). **`SloEvaluator<TContext>`** is an `IServerTask` (§2.3, like `ErrorGroupAggregator`, registered in `AddServerHostCore` — every server, `DisableWorker()` included; cadence `WarpConfiguration.SloEvaluationInterval` default **1m**, null disables) — reads the already-folded `jobstat`/`qwait`/`qbacklog`/`deadline` aggregates via the merged Statistic+Counter read, computes attainment/budget/burn with pure **`SloMath`** (rate `budget = 1 − burn`, `burn = errorRate ÷ allowedError`; threshold `budget = (target − observed)/target`; one `Classify`), upserts `SloEvaluation`, and buffers a breach event dispatched **post-commit from `OnCommittedAsync`** (§8.25 — never `ExecuteAsync`).

**No-data ≠ Healthy:** an objective whose dimension matched **zero** observations in the window is `SloState.NoData` (a typo'd job-type/queue reads distinct from a false green, never alerts); the unknown-`Kind` evaluator arm logs **Error** and reports NoData, never a false Healthy.

**Fast-burn:** short window = `WindowSeconds/12` floored to **5 min**, genuinely populated by reading the **fine tier (§8.30)**; latency kinds read the tiered **`pcth`** histogram (windowed percentiles) over the **job-domain bucket ladder widened to 5 min** (`JobStatsKeys`/`QueueWaitKeys` gain 30s/60s/300s rungs — job execution/queue-wait run past the 10s HTTP-scale top, so a 30s/60s latency target observes and breaches instead of saturating at 10s; one `BucketFor` write per finalization, no hot-path cost).

**Deadline-miss:** derived at finalization from `TimeoutDeadlineUtc` (§8.7) vs the wall clock (nothing added to the fetch/claim loop) — a job reaching **any** terminal state past the deadline is a miss, **including a late `Completed`** (a token-ignoring handler, §8.5); a job the timeout itself ended (`outcome.Reason == Timeout`) is a miss **whatever the clock reads**, because the timeout runs on a timer and finalization compares wall-clock instants, so a job killed at its deadline could be finalized a few milliseconds before it and count as met (caught on CI by `WorkerPathLockstepTests`, both worker paths); one always-on meter + a sink-gated tiered **`deadline`** counter.

**Alerting:** healthy→breaching edge fires `WarpEventType.SloBreached`=7 (`BacklogBreached`=5 wired for depth objectives), once per edge, **ack-suppressed**.

**Read/command:** `ISloQueryService`/`ISloCommandService` registered by `AddWarp` (dashboard-only hosts resolve them); routes `GET/POST/DELETE {prefix}/api/slo(+/{id})` + `/ack`; dashboard **SLOs** page (`/slo`, gated on the `slo` addon flag).

**Metric kinds 6–11 (7.5.0, §8.34):** `SloKind.MetricRatio=6`/`MetricThreshold=7`/`MetricVolumeFloor=8`/`MetricGap=9`/`MetricLatency=10`/`MetricGaugeThreshold=11` hold a custom metric to an objective — `Dimension` = instrument name, `Application` scopes it (null = all), 9 nullable `SloDefinition` columns (`TagFilter`, `SecondaryMetric`, `SecondaryTagFilter`, `RatioTag`, `GoodValues`, `BadValues`, `BaselineDays`, + `Comparison`/`GaugeAggregate` for #331), one `MetricFilter` grammar (`k=v[,k=v]`, trailing `*`, absent tag = `{none}`) shared with the Metrics page. Event quantity = `Sum` (counter/up-down) or `Count` (histogram); gauges rejected by 6–10. **`MetricLatency` (#329)** is framed as a GOOD-EVENT RATIO, not a percentile value: `TargetValue` = threshold in the instrument's unit, `Percentile` 1–99 (default 95, KEPT for this kind only — cleared for 6–9); each `metric_point` row is read as stored (bucket CSVs cannot be summed in SQL — the evaluator's with-buckets read shape) and split on its OWN ladder by `SloMath.TrySplitAtThreshold` — within = buckets whose **upper bound ≤ threshold**, over = the rest incl. the straddling bucket and overflow (resolution = the bucket ladder; a threshold between bounds acts like the lower one) — prorated by overlap, then `EvaluateRate(within, total, Percentile/100)` (allowed slow fraction `1 − p/100`, so burn shares the rate scale); Attainment = share within; NoData when no matching event has bucket counts (a row whose bucket CSV the rollup dropped is skipped). Instrument check is per kind via `SloValidation.AcceptsInstrument` (latency ⇒ histogram only; 6–9 ⇒ not a gauge), shared by the validator (`SloDefinitionValidator` unchanged — it already looks the kind up) and the evaluator (mismatch ⇒ Error log + NoData). The seeder's field match adds the threshold for latency only (two tiers on one histogram differ only there — without it a tier added later matched the old one and was never seeded). UI: `sloForm.acceptsInstrument`/`selectableInstruments(instruments, kind)` limit the picker to histograms; `sloDisplay.formatTarget`/`formatObserved` render `p95 ≤ 0.5` / `97.20% ≤ 0.5`. **`MetricGaugeThreshold` (#331)** is the ONLY kind that accepts a gauge (and accepts only gauges): 2 more nullable `SloDefinition` columns `Comparison` (`SloComparison {AtMost=1, AtLeast=2}`) + `GaugeAggregate` (`SloGaugeAggregate {Average=1, Min=2, Max=3}`), `HasConversion<int>()`, defaulted by validation to AtMost/Average and cleared for every other kind; `Percentile` (1–99, default 95) = the share of OBSERVED TIME that must comply. The evaluator reads the grouped rows (Summed gives Count/Sum/Min/Max — `MetricRawRow` carries Min/Max), combines the matching rows of each (tier, bucket) — counts/sums add, extremes min/max — so **Average = sample-weighted mean across processes and series, never a total** (rollup keeps count/sum/min/max, so a coarse bucket is the average of its samples); `SloMath.TryGaugeVerdict` decides comply/violate (equal complies; no samples / missing extreme / non-finite ⇒ not observed); each bucket weighs the SECONDS it covers in the window (clipped at now) so mixed tiers are not skewed — with only fine rows this is buckets-in-violation ÷ buckets-observed — then `EvaluateRate(compliantTime, observedTime, Percentile/100)`; NoData when no bucket has samples. The seeder's field match adds `Comparison`/`GaugeAggregate` (null on other kinds, so unchanged there) and the threshold. Ratio good/bad lists must not overlap, and with `BaselineDays` the target is the max ratio DROP; Threshold/Gap allow N = 0, and **Threshold is NoData only when the instrument has no rows at all in the window** (traffic with zero matches is Healthy, so "5xx = 0" works); VolumeFloor is NoData on a zero baseline. Window ≥ 600 s; `BaselineDays = 7` needs `HourlyStatisticsRetention` ≥ 7d + window + 1h (R29 — the 7d default rejects it). Every window and baseline read covers ALL tiers overlapping it, prorated by overlap (baselines older than 6h are hourly). **`SloMath.IsNoData` is checked BEFORE `Classify`**: the metric maths return `NoDataResult` (all NaN) for non-finite or overflowing input, and `Classify(NaN)` reads Healthy — never reorder. An instrument of a kind the objective does not accept (`AcceptsInstrument`), an instrument whose registry kind is unknown, and a corrupt stored definition also report NoData (logged at Error). `SloBreachedEvent.Metric` is built from the definition only, never a tag value (§1.2). Builders `AddMetricRatio`/`AddMetricThreshold`/`AddMetricVolumeFloor`/`AddMetricGap`/`AddMetricLatency`/`AddMetricGaugeThreshold`; the seeder match key adds `TagFilter`/`SecondaryMetric`/`RatioTag`/`Percentile`/`Comparison`/`GaugeAggregate` (+ threshold for latency and gauge); the evaluator reads on the server context (§2.14). Worker hot path untouched beyond the one deadline-miss counter (§0.2/§6.1).

**Annotations (#333, §8.34):** an objective can carry `MetricAnnotation` notes (`Target = Slo`, `SloDefinitionId`), shown and edited on the SLO detail page via `GET/POST/DELETE {prefix}/api/annotations?slo={id}`; display only — they never change evaluation, state or alerting (the acknowledged-noise flag is cleared on an SLO note; breaches keep `Acknowledge`), and `SloCommandService.Delete` deletes the objective's notes with it.

**Behaviour changes on this branch (release notes):** (1) `ISloCommandService.Upsert` with an `Id > 0` that names no row returns 0 (route 404 `{ error }`) instead of re-creating the objective, and an `Id ≤ 0` is an insert with the key reset to 0 (store-generated), never the caller's key. (2) On SQL Server the config seeder now matches in memory, like PostgreSQL: names ignore case (OrdinalIgnoreCase), every other matched field (dimension, application, tag filter, secondary metric, ratio tag) is compared exactly (Ordinal) — before, the SQL comparison followed the database's case-insensitive collation, so a seed differing from a stored row only by the case of a field matched it on SQL Server and was inserted on PostgreSQL. (3) A seed is matched only against the rows stored when the pass began, never a seed inserted earlier in the same pass, so config objectives that share a match key on purpose (two `QueueWaitLatency` targets on one queue, a 1 h and a 24 h `SuccessRate` on one job type) are all inserted on a fresh database; target and window stay out of the non-metric key (those kinds have no name fallback, so a dashboard edit of either would reseed a duplicate every restart), which means such a tier added in a LATER deploy still matches the stored one and is not seeded — add it in the dashboard. See `website/docs/features/slo-error-budget.md`.
