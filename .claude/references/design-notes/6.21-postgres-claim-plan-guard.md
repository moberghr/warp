# §6.21 — design notes (postgres claim plan guard)

> Full rationale, history, measurements and rot guards behind the condensed rule §6.21 in `.claude/rules/`. Read on demand when changing this area. Verbatim from the pre-split `performance.md` (2026-11-25).

**§6.21** **PostgreSQL job claims turn `enable_sort` off for their own command** (`PostgresWarpSqlQueries.ClaimPlanGuard`, prepended to both claim forms: `DO $$BEGIN PERFORM set_config('enable_sort', 'off', true); END$$;`; it lasts for the claim's command only, whose statements run as one implicit transaction, and never reaches the pooled connection's next command). It was `SET LOCAL`, which PostgreSQL answers outside an explicit transaction block with `WARNING: SET LOCAL can only be used in transaction blocks` while still applying it: a server-log line per claim, empty polls included. `set_config(..., true)` has the same scope and no warning; it sits in a `DO` block because the command must not return a result set before the claim's own (EF reads the first). Rot guard: `ClaimPlanStabilityTests.ClaimEnqueuedJobs_EmptyQueue_RaisesNoServerNotice`. After a burst into a queue the last analyze saw (nearly) empty, the planner estimated the claim at one row and chose the dashboard's `(kind, current_state, create_time)` index: every enqueued row of the kind, filtered by queue and sorted, to return the limit. CI, 50k jobs: 48,020 rows, 22.8 ms and ~22,000 buffers per claim against 0.72 ms and ~375, throughput capped at ~700-1,200 jobs/s until autovacuum analyzed the table (6-11 s there; on a table holding millions of history rows a burst of a few percent may not trigger an analyze until the drain itself has churned enough rows). With sorting priced out, the only plan left is the claim index read in schedule order: the same rows in the same order, so the setting changes the plan, never the result; a host that removed the claim index still gets a (sorted) plan. It was present in `main` too (the whole claim index loses the same way), not introduced by §6.15. Rot guards: `ClaimPlanStabilityTests.ClaimEnqueuedJobs_BurstIntoAQueueTheStatisticsSayIsEmpty_UsesTheClaimIndexWithoutSorting` (replays the claim's command and EXPLAINs it on the stale statistics CI captured; fails without the guard) and `SetLocalInAMultiStatementCommand_LastsForThatCommandOnly`.
