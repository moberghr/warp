# §2.3 — design notes (server tasks)

> Full rationale, history, measurements and rot guards behind the condensed rule §2.3 in `.claude/rules/`. Read on demand when changing this area. Verbatim from the pre-split `architecture.md` (2026-11-25).

**§2.3** Every background task implements `IServerTask` (`Name`, `LockKey`, `DefaultInterval`, `ExecuteAsync`) and is registered as scoped. `ServerTaskHost<TContext>` splits them once: a task with a `LockKey` is cluster-wide and is claimed once per tick for the whole cluster through its `ClusterTask` row by one `ClusterTaskScheduler` per server (§6.23); a task without one (the heartbeat) runs on its own `PerServerTaskLoop`. Both run a task through `ServerTaskRunner`, the one place that knows how a task executes. Active tasks: **on every server** (`AddServerHostCore`, `DisableWorker()` included) `Heartbeat`, `ServerCleanup`, `ExpirationCleanup`, `StatisticRollup`, `MetricRollup`, `CounterAggregator`, `ErrorGroupAggregator`, `SloEvaluator`; **job-only, with a worker** (`AddWarpServerCore`) `StaleJobRecovery`, `WebhookEndpointMonitor` (8.1), `BacklogSampler`, `RecurringJobScheduler`, `ScheduledJobActivation`, `MessageRouter`, `Orchestrator`; plus `NotificationListenerTask` (when DB push is enabled). The folds that read rows any process may write are cluster-locked and live in `AddServerHostCore` so a service-only server runs them (§2.13, §8.18).
