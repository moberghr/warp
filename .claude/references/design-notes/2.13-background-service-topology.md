# §2.13 — design notes (background service topology)

> Full rationale, history, measurements and rot guards behind the condensed rule §2.13 in `.claude/rules/`. Read on demand when changing this area. Verbatim from the pre-split `architecture.md` (2026-11-25).

**§2.13** `WarpBackgroundService` is a base part of Warp (no addon opt-in). `AddWarp<TContext>` always contributes the four entities (`Definition`/`Instance`/`Lease`/`Log`) to the model **and** registers `IBackgroundServiceQueryService` (read-only — needed by dashboard-only / publisher-only processes that never start a server). `AddWarpServer<TContext>` adds the server-side pieces: `BackgroundServiceHost<TContext>`, the lease coordinator, the state service, and the log store, plus (unless `opt.DisableWorker()`) the job worker hosts and the six job-only server tasks (`StaleJobRecovery`, `BacklogSampler`, `RecurringJobScheduler`, `ScheduledJobActivation`, `Orchestrator`, `MessageRouter`). **The worker is a component of the server** — `opt.DisableWorker()` (sets `RunWorker = false`) gives a service-only server: shared server-host infra (server registration, `ServerTaskHost`, `BackgroundServiceHost`, `Heartbeat`/`ServerCleanup`/`ExpirationCleanup`) **and the cluster-locked aggregation folds** (`StatisticRollup`, `MetricRollup`, `CounterAggregator`, `ErrorGroupAggregator`, `SloEvaluator` — the last three moved here from the worker-only block in 7.5.0, so a `DisableWorker()` server now runs them; it still never claims a job) with no worker hosts/job-only tasks and no `Worker`/`WorkerGroup` rows (`WarpServerRegistration` skips groups when `!RunWorker`). A provider is still required (server tasks take locks). The worker-on path and the service-only path share a private `AddWarpServerCore<TContext>(services, runWorker)` → `AddServerHostCore<TContext>`. Users register their own services with `opt.AddBackgroundService<T>()` (single type parameter — the receiver `IWarpBuilder` is non-generic for addons that don't need `TContext`). `PerServer` scope runs an independent instance on every server; `Singleton` scope coordinates via `BackgroundServiceLease` (30s TTL, renewed in `Heartbeat` ~5s cadence, ~30s worst-case failover on hard-kill / ~0s on graceful shutdown). Lease loss signaled via `ServerTaskSignals<TContext>.PublishBackgroundServiceLeaseLost`. Orphaned `BackgroundServiceDefinition` rows (renamed/removed services with no live `Instance`) are removed by `ExpirationCleanup` once `LastSeenAt` exceeds `WarpConfiguration.BackgroundServiceDefinitionOrphanGrace` (default 2 min). Worker hot path untouched (§0.2/§6.1) — separate `BackgroundServiceHost<TContext>` drives supervisor loops. See `website/docs/features/background-services.md`.
