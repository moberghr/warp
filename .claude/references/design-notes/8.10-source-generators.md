# §8.10 — design notes (source generators)

> Full rationale, history, measurements and rot guards behind the condensed rule §8.10 in `.claude/rules/`. Read on demand when changing this area. Verbatim from the pre-split `project-specific.md` (2026-11-24).

**§8.10** Source generators (`Warp.SourceGenerator`, `Warp.Http.SourceGenerator`) target `netstandard2.0` and provide zero-allocation mediator dispatch and HTTP endpoint generation. **The worker runs jobs and messages through the generated dispatch too** (8.0): each assembly's `GeneratedJobDispatcher` has its own `[ModuleInitializer]` that hands one typed delegate per job/message type to `WarpGeneratedHandlerRegistry.AddJobDispatch` (public, because generated code in consumer assemblies calls it; first registration per type wins, they are equivalent), and `JobDispatcher.ExecuteHandlerCore` uses it before its reflection path, which stays for types no generator saw (a handler registered by hand in an assembly without the generator). Until then the generated dispatcher was emitted and never called by the worker: every job paid two `MethodInfo.Invoke` calls (argument arrays, a boxed token) and a handler-enumerable search. The generated job method resolves `IJobHandler<T>` and falls back to the enumerable only when the row names a handler other than the last registered. A handler that throws synchronously now surfaces its own exception rather than a `TargetInvocationException` (the error-grouping unwrap stays for the fallback). The worker's per-job log lines are `[LoggerMessage]` (`WorkerLog`). **The generated dispatch stays out of a failed job's stack trace**: that trace is stored per failure (the failure `JobLog` and the `ErrorOccurrence`), and its first generated form added two frames carrying the job type's full name and the `obj/GeneratedFiles/...g.cs` path, +15-16% WAL per failed job on the failure-path and retry benchmarks. The per-type `Execute_*` methods are not `async` (a synchronous throw is returned as a faulted task), the handler's `Task` becomes `Task<Unit>` through one named `AsUnit` helper rather than an async lambda, and the class is emitted under `#line hidden`, so the only plumbing frame left is `AsUnit(Task handling)` with no path: 625 characters against 1,174 on the reflection path. `[StackTraceHidden]` does not work here (the runtime checks the async state machine, not the declaring method). Rot guards: `GeneratedJobDispatchTests` (the synchronous-throw test fails on the reflection path; `ExecuteJobHandler_HandlerFails_StackTraceCarriesNoGeneratedPlumbing`). `[WarpHttpGet/Post/Put/Patch/Delete]` annotations on handler classes emit `RequestDelegate`s; `IJob` / `IMessage` rejected at compile time (`WHTTP001`).

**Binary I/O:** a handler whose response is `Microsoft.AspNetCore.Http.IResult` (`IRequest<IResult>`) owns the full HTTP response — `JsonResponseWriter` detects `IResult` and calls `ExecuteAsync`, skipping the JSON envelope, so `Results.Stream/File/Bytes/NotFound/Ok` all work (used for file serving, bodyless status codes).

**Multipart/form uploads:** request members typed `IFormFile`/`IFormFileCollection`/`IFormCollection` or carrying `[FromForm]` bind from the form (`BindingSource.Form`, emitted as a `Mixed` shape); `MapWarpHttp` sets `multipart/form-data` and `DisableAntiforgery()` on those endpoints. A request cannot bind both a form and a JSON `[FromBody]` (`WHTTP006`). Demo endpoints: `Warp.Test.Shared/HttpEndpoints.cs` — `/http/file-echo` (upload a file, echo its contents) and `/http/text-to-file` (send text, download it as a file). **`WARP003` — a contract nothing handles** (`UnhandledJobValidator`, prior art PA-05): the mediator generator already knows every `IJob`/`IMessage` and every handler beside it, and a contract missing from that map fails only when a worker picks the row up (`No handler registered for X`) — §8.8's criterion ("what no execution path can honour") covers it.

**Warning, never error, and the exemptions are the whole design:** a compilation cannot see an assembly that references it, so a project declaring **no** job-family handler at all is a contracts project and is skipped wholesale (the shared-contract layout stays silent); saga messages count as handled via `ISagaHandler<TSaga, TMessage>` (the user's handler never implements `IMessageHandler<T>` — `AddSagaHandler` registers a proxy, so the message is absent from the dispatch map); self-handling jobs are already their own map entry; open generics are skipped (the map keys a closed type); and referenced contracts are never this compilation's to report. Unhandled `IRequest<T>`/`IStreamRequest<T>` are deliberately **out of scope** — they throw on the calling thread at `Send`/`CreateStream`, and the asymmetry the diagnostic exists for is that a job fails later, elsewhere. What survives suppresses with `#pragma warning disable WARP003`. `Warp.Tests` carries a project-level `NoWarn` because its fixtures are handler-less by design; `UnhandledJobDiagnosticTests` drives the generator in-process and is unaffected.
