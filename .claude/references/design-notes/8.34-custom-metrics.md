# §8.34 — design notes (custom metrics)

> Full rationale, history, measurements and rot guards behind the condensed rule §8.34 in `.claude/rules/`. Read on demand when changing this area. Verbatim from the pre-split `project-specific.md` (2026-11-24).

**§8.34** **Custom application metrics (7.5.0)** — Warp is a **collector** of the standard `System.Diagnostics.Metrics` API, not an emit API: host code uses `IMeterFactory`/`Counter<T>`/`Histogram<T>` and takes no Warp dependency. **Opt-in** `opt.AddMetrics(m => …)` (`Warp.Core.Metrics`, non-generic `IWarpBuilder` receiver, inside the `AddWarp`/`AddWarpServer` lambda; merges on repeat) — `WarpMetricsOptions.CollectMeter`/`Instrument`/`KeepTags`/`Buckets`/`CollectAspNetCoreHttp`/`CollectHttpClient` (presets are config strings, `Warp.Core` takes NO ASP.NET Core dependency; server keeps route/method/status, client method/server.address/status/error.type); nothing collected without it, byte-for-byte unchanged.

**Collector:** `WarpMeterCollector` (`MeterListener`, started by `MetricCollectorHost`) enables only instruments of named meters by exact ordinal meter name and **never the `Warp` meter** (double-count); callback is in-memory only (no I/O, never throws — counted on `warp.metrics.collapsed{reason=error}`); `MetricKind {Counter=1,UpDownCounter=2,Histogram=3,Gauge=4}`; an `ObservableCounter` sums per series per pass then records the delta vs the previous pass (first pass = baseline, a decrease = reset); non-finite values are dropped. Histogram bounds precedence **config > `InstrumentAdvice` > unit default** (`s`/`ms`/OTel ladder), ≤ 20 strictly increasing, stored rounded to 7 significant digits and **≤ 256 chars as CSV (throws, never truncates — truncation misaligns counts)**; rows with different bounds never merge. **Series** = (instrument, `ApplicationName`, canonical `k=v,…` tag set sorted ordinal after the `KeepTags` allowlist; values invariant, trimmed, **truncated to 64**, null/empty → `{none}`, `,`/`=` → `-`), plus `ApplicationVersion` ONLY with `AddMetrics(m => m.ByVersion())` (#330); the application and version are dimensions, never read from a tag.

**Version dimension (#330):** `WarpMetricsOptions.CollectByVersion` (set by `ByVersion()`, default false) → `WarpMeterCollector(…, version)` (ignored without `ApplicationName`, sanitized via `MetricPointQueries.NormalizeVersion`) → `MetricInstrumentCardinality` → `MetricSeries.Version` (in hash + equality) → nullable `metric_point.Version` (128). Off ⇒ the column is null and every row is what it was. `MetricRollup.SeriesKey` carries `Version` (ordinal, in memory, like `Application`), so compaction and both tier passes keep versions apart. Read: the reserved pseudo-tag **`MetricSeriesQuery.VersionKey` = `{version}`** — injected into each row's parsed tag dictionary ONLY when the row has a version (absent ⇒ `{none}`, so `*` never matches a version-less row, the matcher's absent-tag rule), so `breakdown={version}` and `filter={version}:2.*` go through the ONE breakdown path and the ONE `MetricFilter`; `MetricPointQueries.Summed(…, byVersion)` groups by `Version` for the dashboard's tag-level reads only — the total read and the SLO evaluator are unchanged (the SLOs ignore versions). Because the SLO evaluator and the board never inject the pseudo-tag, `SloValidation` and `MetricBoardValidation` REJECT `{version}` as a `TagFilter`/`SecondaryTagFilter` key or a `RatioTag` (`MetricFilter.Constrains` + `MetricFilter.ReservedVersionKeyError`; 400 on the routes, throw from the builders) — a stored filter on it would never match. `MetricAnnotationValidation` keeps accepting it: an annotation filter only widens (a note is shown when it overlaps). UI: `metricModel.VERSION_KEY`/`dimensionKeys`/`dimensionLabel` put "application version" in the breakdown and filter pickers (the filter form now always shows). **Units are displayed through ONE helper, `lib/metricUnit.ts` `unitLabel(unit, count?)` / `withUnit(text, unit, count)`** (re-exported by `metricModel`): `1` → nothing, `By` → bytes, a UCUM annotation `{x}` (a dimensionless count of x) → the word, naively pluralised unless the count is exactly 1 (no count = plural, for axis titles and the Metrics list's unit column), compound `{request}/s` → `requests/s`, an annotation attached to a unit (`ms{server}`) dropped, every other unit unchanged. Every call site (detail header + headline, axis titles, percentile values, board tile values, the list's unit column) goes through it — do not print `instrument.unit` raw; it rendered `30,159 {callback}` and `Sum ({checkout})`. **Cardinality** (`MetricCardinalityGuard`, per process, §8.27 shape): `MaxTagsPerInstrument` 6, `MaxValuesPerTag` 100 (→ `{other}`), `MaxSeriesPerInstrument` 500 (→ `{other}` tag set), `MaxInstruments` 300 (further instruments are never enabled, reported under `{other}`); reasons `tag_values`/`series`/`tag_count`/`instrument_cap`/`name_conflict`/`name_too_long`/`tags_truncated`/`bounds`/`error`, reported as a Warning once per (instrument, tag key, reason), the always-on `warp.metrics.collapsed{instrument,reason}` meter and the `metric_instrument.CollapsedAt/CollapsedTags` badge — **a report NEVER includes a tag value (§1.2)**; caps are per process, so N processes can store up to N× the cap.

**Aggregation/flush:** `MetricAggregator` keeps series × 5-min bucket → {count,sum,min,max,buckets} (count/sum under a per-aggregate lock, NOT `Interlocked` — a sealed-drain correctness deviation; `Drain` takes each entry with `TryRemove`, `MergeBack` is additive, both pinned by an N=2 `BarrierSignal` test); `MetricFlusher` is a per-process `BackgroundService` (not a locked `IServerTask`, the `DroppedRecordReporter` §8.32 shape: aggregates are per process, so every process writes its own) that every `MetricFlushInterval` (30s, must be > 0) reads observables then inserts one **partial** fine `metric_point` row per drained series, and once more on graceful `StopAsync` (registered after the collector host so it stops first and the final drain still sees the listener); an ungraceful exit loses at most one interval; measurements are NOT transactional; an idle aggregator does no DB work; a failed point write merges back, the `metric_instrument` registry is upserted in a SEPARATE `SaveChanges` (new / hourly-refresh / newly collapsed; a PK race retries row by row, Debug then Warning on two consecutive conflicts) and never fails or re-adds points. Sink seam `IMetricPointSink`: `ContextMetricPointSink<TContext>` (`TryAddScoped`, AddWarp-only, user `TContext` §2.15) is replaced by `ServerMetricPointSink` (`IWarpServerContext`, §2.14) via `Replace` in `AddServerHostCore` whichever call ran first. **Storage** (`Warp.Core.Data.Entities`, always-in-schema §2.11, mirrored §2.14): `MetricPoint` (Instrument 128, Application?, Tags 512 canonical or `-`, `Tier` = the existing `MetricTier` **promoted to public**, `BucketStart`, Count, Sum, Min?, Max?, Buckets/Bounds CSV, `Compacted`; indexes `(Instrument,Tier,BucketStart)` for reads and `(Tier,Compacted,BucketStart)` for rollup) + `MetricInstrument` registry (PK Name; first publisher of a name wins on (meter, kind, bounds); `ExpirationCleanup` deletes rows unseen past `DailyStatisticsRetention`, `FindEntityType`-guarded). Migration is **additive**: 2 tables + 9 nullable `slo_definition` columns (7 + `Comparison`/`GaugeAggregate`, #331), generated by the host's `dotnet ef migrations add`.

**Rollup:** `MetricRollup<TContext>` is an `IServerTask` registered in `AddServerHostCore` (so every server, `DisableWorker()` included; `LockKey="warp:metric-rollup"`, `MetricRollupInterval` 1m, `null` disables; transaction-scoped lock §2.16) running three bounded passes that SHARE `MaxMetricRollupRowsPerTick` = 20,000 source rows (§6.2.1 — never remove the cap): **compact** closed fine buckets (`BucketStart + FineResolutionMinutes + 2×MetricFlushInterval < now`) into one `Compacted` row per (Instrument, Application, Tags, BucketStart, Bounds), **fine → hourly** past `FineResolutionRetention`, **hourly → daily** past `HourlyStatisticsRetention`, then prune daily past `DailyStatisticsRetention`; every pass saves the parent sums BEFORE deleting its sources **by the ids actually summed (never by predicate — the capped pass defers rather than drops; an id-based-delete mutation fails the cap test)**, keys are matched in memory with ordinal comparison so a case-insensitive collation can only widen a candidate fetch, and an idle tick returns null with `RerunImmediately`. **Reads sum on read** — the newest fine rows are still partial, so compaction is an optimisation, never a correctness requirement. `IMetricQueryService` (`AddWarp` itself, dashboard-only hosts resolve it): display resolution ≤ 6h fine / ≤ 7d hourly / else daily; **the read covers EVERY tier overlapping `[From,To)` and re-bins** (fine rows only reach hourly after 6h, so a single-tier read misses the newest data; no double counting because a rollup deletes each source in the transaction that adds it to its parent); each series is labelled with the coarsest resolution it contains; three read shapes (total grouped in SQL when there is no filter/breakdown; series grouped in SQL; bucket CSVs parsed ONLY for a percentile); breakdown = top 10 by headline value + `(rest)`; filters use the ONE `MetricFilter` matcher shared with the SLOs; compare `1d`/`7d`; percentiles are bucket upper bounds; the current range's **still-filling bucket** (the display bucket holding `now − MetricFlushInterval` and later, read off the injected `TimeProvider`) is flagged `Incomplete` and the per-range `Headlines` (current + each overlay, every line incl. `(rest)`) sum **complete buckets only** — overlays drop the bucket aligned with it, never prorated, `CompleteUntil` marks the cut; ranking still uses the whole range (#328); each point carries `BucketSeconds` (max of display tier and the coarsest stored row in it, fine = `FineResolutionMinutes`), which the page's per-bucket/minute/second toggle (`?rate=` in the URL, counters + histogram counts only, never ratio/percentile) divides by client-side (#335).

**Custom range + deploy markers (#327):** the detail page's range lives in the URL (`?range=<preset>`, default `24h` left out; or `?from=<ISO>[&to=<ISO>]`, no `to` = "until now", a live window) — `metricModel.parseRangeParams`/`writeRangeParams` round-trip it, `resolveWindow` cuts a start older than `MAX_RANGE_MS` (90 d, the API limit) and keeps ≥ 1 min before the end so the read is never a 400, `validateCustomRange` gates the picker, and `seriesRefetchMs(window)` returns `false` for a window that already ended. Resolution and overlays need no client logic: the server picks the tier from `to − from` and shifts the same `from`/`to` for `compare`. Deploy markers come from `GET applications/deploys?application=&from=&to=` (#325, §8.23) bounded by the SERIES response's own `from`/`to` (not the render clock, so the chart only redraws on new data) and are drawn by an inline Chart.js plugin; "Since last deploy" = `{ from: newest deploy, to: null }`, scoped to the selected application, or to every application when none is selected. Render-time "now" goes through `useTickingValue` (the React compiler's purity rule rejects `Date.now()` in render). API `GET {prefix}/api/metrics` and `GET {prefix}/api/metrics/{id}/series` (`{id}` = `UrlSafeId` of the instrument name; `from`/`to` ≤ 90 days, repeated `filter=key:value`, `compare=1d,7d`, `percentile` 1–99; bad input is a 400); `WarpAddonsInfo.Metrics` keyed on `IMetricsMarker`, `ShowMetrics()` for dashboard-only hosts, `WarpDashboardPage.Metrics`.

**Known read limits (documented, not fixed):** SQL Server's case-insensitive collation merges tag sets differing only by case into one series; under locking READ COMMITTED (no RCSI) a read racing a rollup can transiently double-count one bucket; baselines older than 6h are hourly and prorated.

**Measured (PostgreSQL, 1.58M rows, 500-series cap, SC9):** 24h and 7d total-only reads ~31 ms warm, 7d breakdown ~1 s, 7d percentile + breakdown ~0.8 s — the 250 ms gate applies only to the common (no percentile, no breakdown) reads, the others are documented worst cases (spec amendment 2026-11-15); **callback cost (SC10, `MetricCollectorBenchmarks`, ShortRun, warm series, 3 tags):** counter ~253 ns / histogram ~249 ns, 0 B allocated.

**PCI/PII (§1.2 — Warp cannot detect PII in a free string):** tag values must NEVER carry PAN, PII or customer identifiers; `KeepTags` allowlists on any instrument whose tags you do not control; 64-char truncation is a size control, not a privacy one; adapter capture stays `None` for payment processors and `ForceCapture` is never used on them (`custom-metrics.md`, `adapters.md`).

**Topology:** `CounterAggregator`/`ErrorGroupAggregator`/`SloEvaluator` moved into `AddServerHostCore` beside `StatisticRollup`/`MetricRollup` (§8.18/§2.13 — a `DisableWorker()` server now runs them, a release-note behaviour change) while the six job-only tasks stay in `AddWarpServerCore`; worker hot path untouched (§0.2/§6.1). SLO kinds 6–9: §8.31.

**Rot guards:** `ServiceRegistrationTopologyTests` + `DeploymentShapeTests` (task sets per shape), `MetricSeriesTests`/`MetricBucketsTests`/`MetricCardinalityTests` (canonical form, bounds precedence, caps + report-once + fuzz), `WarpMeterCollectorTests` (every kind, `Warp` meter ignored, N=2 concurrency — **unique meter name per test, `MeterListener` is process-global**), `MetricAggregatorTests` (lossless drain, additive merge-back), `MetricFlusherTestsBase`, `MetricRollupTestsBase` (compaction exactness, cap defers without loss, bounds kept apart), `MetricQueryServiceTestsBase` (multi-tier, partial rows, breakdown, filters, overlays, percentile), `MetricFilterTests`, `MetricSloEvaluatorTestsBase`, `SloMathTests`/`SloValidationTests`, `HostDbContextCoexistenceTestsBase` + `MediatRCoexistenceTests` (host interceptor unchanged, migration differ includes the `warp` tables, MediatR 12.5.0 unaffected), `CustomMetricsEndToEndTestsBase` (`HeavyIntegration`: `AddWarp`-only host → `metric_point` → `DisableWorker()` server rolls up and fires a metric SLO edge, a seeded `Enqueued` job stays `Enqueued`); `WarpTestServer` nulls `MetricRollupInterval` and `IdleLoopSwitches` lists it (neighbour-contention switches).

**Health board (#326):** `MetricBoardTile` (`Warp.Core.Data.Entities`, always-in-schema §2.11, mirrored §2.14 via `ApplyWarpModel`; one additive table `metric_board_tile`) = an instrument + optional `MetricFilter` tag filter + `MetricTileKind {Value=1, Ratio=2}` (ratio = good/bad CSV on one tag, the `MetricRatio` rule; value = events, or a gauge's `SloGaugeAggregate`) + `MetricTileStatusRule {None=1, Threshold=2, Deviation=3}` (`Comparison`/`Threshold`; or `BaselineDays` 1|7 + `MaxDeviation` + `MetricDeviationDirection {Drop=1, Rise=2, Either=3}`, a fraction of the baseline on a value tile and ratio points on a ratio tile). `MetricBoardValidation.TryValidate` is shared by the upsert route and the seeder via `MetricBoardTileValidator` (registry kind looked up like `SloDefinitionValidator`): a ratio refuses a gauge, the aggregate is kept only on a gauge, fields of other kinds/rules are cleared, `MaxTiles` = 48. `IMetricBoardQueryService`/`IMetricBoardCommandService` are registered by `AddWarp` (dashboard-only hosts, no `AddMetrics`); `opt.AddMetricBoard(b => b.Value(…).Ratio(…))` only adds the insert-if-absent `MetricBoardSeeder` hosted service (match by name OR instrument+kind+application+filter+ratio tag+aggregate, after validation; merges on repeat; a name match with different fields logs Information with the differing field names).

**Seed and cap race:** the seeder's read + inserts and `MetricBoardCommandService`'s count-then-insert run under ONE transaction-scoped lock `warp:metric-board` (`TransactionLock`, §2.16 — try-lock retried until the holder commits; the command takes `IWarpSqlQueries<TContext>?` as an optional ctor param so a provider-less dashboard host still resolves it, unguarded), so N replicas seed one copy and two inserts cannot both pass `MaxTiles`; rot guards = the N=2 `BarrierSignal` seeder race tests in `MetricBoardTestsBase`/`SloCommandQueryTestsBase`. An edit (`Id > 0`) of a deleted tile returns 0 → route 404 `{ error }` (it used to re-create the tile); an insert resets an `Id ≤ 0` to 0 (a negative key reached SQL Server as an explicit identity value: 500); an insert that cannot take the lock within `TransactionLock.CommandTimeout` (10 s) throws `TimeoutException` → route **503** `{ error }` (busy, retryable — not the unhandled 500); rot guards also cover the lock held from a second connection (N=2, the insert waits), the timeout and the provider-less path.

**Window cut (#328 rule on the board):** the current value AND both shifted baselines stop at `MetricBoardModel.CompleteUntil` = fine `BucketStart(now − MetricFlushInterval)` clamped to `[From, To]` (ALWAYS at fine-bucket granularity, whatever the range — unlike `MetricQueryService.CompleteCutoff`, which cuts at the start of the DISPLAY tier's bucket, hourly or daily for a long range) — a still-filling newest bucket against complete baselines read every deviation tile as a drop; sparklines still run to `To`; nothing complete ⇒ NoData.

**Batched read:** `MetricPointQueries.InBoardWindows` ORs the `InRange` tier bounds of the current, −1d and −7d windows for every tile instrument, and `SummedForBoard` groups per (instrument, application, tier, bucket[, tags]): ≤ 2 statements + the registry read per board, whatever N, never a scan of the days between windows (`GetBoard_StatementCount_DoesNotGrowWithTheTiles` counts them with a `DbCommandInterceptor`: tiles + registry + annotations + ≤ 2, equal for 3 and 6 tiles). Each window prorates buckets by overlap through `MetricWindows` (the written-width-clipped overlap the `SloEvaluator` now delegates to: shared, not copied). Pure maths in `MetricBoardMath`; status via `SloMath.EvaluateBound` (= `EvaluateCount` for at most a positive target; on a RATIO tile at least is the `EvaluateRate` budget `(obs − t)/(1 − t)` — the plain headroom `(obs − t)/t` can never reach `Classify`'s 0.25 on a 0–1 ratio, so AtLeast(0.98) was never Healthy; at `t ≥ 1` it is all-or-nothing like `EvaluateRate` (exactly 1.0 Healthy, below Breaching — it once read Warning at a perfect 1.0); a ratio tile's `Threshold` is bounded to [0, 1] by `MetricBoardValidation` (route 400, seeder skip)) and `SloMath.EvaluateDeviation` (`EvaluateVolumeFloor` / `EvaluateRatioDrop`, plus the new `EvaluateVolumeCeiling` for rises; Either = the side with less budget), with `IsNoData` before `Classify`. NoData = empty window (an instrument with rows but no match reads 0), a non-positive value baseline, an unknown instrument, a kind mismatch. API `GET {prefix}/api/metrics/board?from=&to=` (shared `MetricSeriesRequestParser.TryParseRange`, 400 on bad input), `GET/POST {prefix}/api/metrics/board/tiles`, `DELETE …/tiles/{id}`. UI: the **Board** tab (`/metrics/board`, `MetricBoardPage`, `MetricsTabs`), pure `boardModel`, range in the URL via the #327 `metricModel` helpers incl. "Since last deploy", sparklines with the deploy plugin extracted to `lib/deployMarkerPlugin.ts` (shared with the metric chart); demo fixtures `demo/data/metricBoard.ts`. Rot guards: `MetricBoardTestsBase`, `MetricBoardMathTests`, `MetricBoardValidationTests`, the topology tests (AddWarp-only resolves the board, one seeder), `boardModel.test.ts`.

**Named boards:** `MetricBoard` (`Warp.Core.Data.Entities`, always-in-schema §2.11, mirrored §2.14 via `ApplyWarpModel`; one additive table `metric_board`: `Name` ≤ 200, `Description?` ≤ 500, `Position`, `Application?` ≤ 200 (the picker's default scope, never a tile filter), **`IsDefault`**, `CreatedAt`/`UpdatedAt`, `CreatedBy?` = `DashboardUser.Name`) + nullable **`MetricBoardTile.BoardId`**, a SOFT reference (no FK, the `SloDefinitionId` precedent), index `(BoardId, Position, Id)` replacing `(Position, Id)`. **Null = the Default board**, so legacy tiles need no data migration, and the command service and the seeder STORE Default's tiles as null (a tile upserted with the Default board's id is normalized to null): one representation; reads still accept the Default id defensively. **Name uniqueness ignores case and is enforced in memory under the lock, never by a unique index** (collations differ). The **Default board** is identified by `IsDefault` (an extra column beyond the spec's field list: "its id is stored" needs a durable marker that survives a rename), created ONCE by `MetricBoardStore.EnsureDefaultAsync` under the `warp:metric-board` transaction lock — by `IMetricBoardCommandService.EnsureDefaultBoard` (unlocked read first; the lock only on first use), by a board insert, or by the seeder — and can be renamed but never deleted (400). `GET {prefix}/api/metrics/boards` calls `EnsureDefaultBoard` before listing so the picker always has a real id; `IMetricBoardQueryService.GetBoards` alone lists a VIRTUAL Default (id 0) when the row was never created, which the verdict and `GetBoard(from,to)` handle.

**Caps:** `MaxTiles` 48 PER BOARD (counted on the target board; a move onto a full board returns null → 400), `MaxBoards` 100. **Every tile write now runs under the board lock** (insert AND edit — the edit can move a tile, which must not land on a board being deleted or past the cap), so an edit can now 503 too. `Upsert` returns 0 for a deleted tile OR a deleted target board (route 404 `{ error }`). Board writes: `UpsertBoard(board, actor)` → `MetricBoardWriteResult {Saved, NotFound (edit of a deleted board → 404, never re-created), NameTaken, Full}` (400s), `DeleteBoard(id, actor)` → `MetricBoardDeleteStatus {Deleted (204), NotFound (404), DefaultBoard (400)}`, deleting the board AND its tiles in ONE `SaveChanges`; audit `Metric board {Id} created|updated|deleted by {Actor}`. Read: `GetBoard(from,to)` = Default (tiles `BoardId == null || == defaultId`), `GetBoard(id, from, to)` → null for an unknown id (route 404), `GetAllBoards` (verdict only), each ONE board-row statement more than before (statement test bound 5 → 6, still flat in tiles and boards). `MetricBoardModel.Board` is the board read (null for all boards); `MetricBoardTileModel.BoardId` as stored. Routes: `GET/POST {prefix}/api/metrics/boards`, `DELETE …/boards/{id}`, `GET …/metrics/board?board={id}` (absent = Default; non-numeric/≤ 0 → 400; unknown → 404), tile upsert body `boardId` — **on an INSERT null = Default; on an EDIT null/omitted keeps `existing.BoardId`** (an omitted `boardId` once moved a named-board tile to Default; the request cannot tell omitted from explicit null, so an explicit move to Default sends the Default board's REAL id, which the dashboard's Board select already does via `tileBoardValue`; rot guards `Upsert_EditWithoutABoardOfATileOnANamedBoard_KeepsItOnItsBoard` / `Upsert_EditWithTheDefaultBoardsId_MovesTheTileToDefault`).

**Seeding:** `opt.AddMetricBoard("Name", b => …)` (the unnamed overload and the name `Default`, ignoring case, are the Default board); repeated calls merge per board into ONE `MetricBoardSeeds` singleton (replacing the `MetricBoardOptions` singleton); a named board is seeded even with no tiles. Under ONE lock the seeder ensures Default, matches each seed board by name OrdinalIgnoreCase (missing ⇒ created, flushed for ids inside the lock transaction, capped at 100), then matches tiles ONLY against the same board's tiles (name OR `SameFields`, the 48-tile cap per board) — the same tile name on two boards is fine.

**Seed key:** a seeded board stores the name the code declared in the nullable `MetricBoard.SeedKey` (≤ 200; additive column `metric_board.seed_key`), and the seeder matches a seed by `SeedKey` first, then by name (both OrdinalIgnoreCase, in memory, under the same lock) — a dashboard rename keeps `SeedKey`, so the renamed board is still found and the seed never re-creates a second board under the old name (the SLO/tile seeders' rule). Boards created in the dashboard have no `SeedKey`; a seed that finds one by name stamps it (adoption). A name match whose `SeedKey` belongs to ANOTHER seed (that seeded board was renamed onto this seed's name) is skipped and logged at Error — names stay unique. **The name fallback never matches the `IsDefault` board for a NAMED seed** (`MatchSeed` excludes it): with Default renamed to "Checkout", `AddMetricBoard("Checkout", …)` once matched it, put its tiles on Default with no seed key, and seeded them a second time on a new Checkout board after Default was renamed back. It is now skipped and logged at Error (the same rule as the renamed-seed collision; creating the board would break name uniqueness) until one is renamed; rot guards `Seeder_DefaultBoardRenamedToTheSeedName_*` / `Seeder_DefaultBoardRenamedBackAfterASkippedSeed_*` (both DBs). UI: board picker (`BoardPicker`/`BoardForm` in `MetricBoardPage`) + pure `boardsModel.ts`: URL id = slug of the name (`boardSlug`; a later board whose slug is taken gets `slug-{id}`, and when THAT is taken too ("x 9" holds `x-9` before board 9 "x." asks for it) a counter `-2`, `-3`, … until unused — every id is checked against the taken set, `boardUrlIds`), `?board=` absent for Default, `selectBoard` = URL → last board (localStorage `warp:metrics:lastBoard`, every access in try/catch) → Default, a URL naming no board is reported and falls back; delete through `ConfirmDialog` with the failure shown; the tile editor's **Board** select moves a tile; demo boards Default/Checkout/Payments (`demoBoards`, `demoMetricBoard(…, board | 'all')`, demo verdict `board`). Rot guards: `MetricNamedBoardTestsBase` (both DBs: CRUD, name taken ignoring case, edit of a deleted board, both caps, Default created once under an N=2 seeder pin, Default undeletable, delete removes only its tiles, legacy null tiles on Default, per-board read + statement count, moves, seeder by name across boards + idempotent + dashboard edits survive + N=2 `BarrierSignal` race, routes 400/404, dashboard-only host), `DeployVerdictTestsBase` (no board = every board; board narrows, case-insensitive, Default; unknown 404), `MetricBoardValidationTests`/`DeployVerdictQueryTests` (NoDb), topology (seeds merge by name), `HostDbContextCoexistenceTestsBase` (`warp.metric_board`, nullable `board_id`, no FK), `boardsModel.test.ts`, `demoBoards.test.ts`.

**Annotations (#333):** `MetricAnnotation` (`Warp.Core.Data.Entities`, always-in-schema §2.11, mirrored §2.14 via `ApplyWarpModel`; one additive table `metric_annotation`, indexes `(Instrument, StartsAt)` + `SloDefinitionId`) = a known-issue note (≤ `MetricAnnotationValidation.MaxNoteLength` 500) on `MetricAnnotationTarget {Instrument=1, Slo=2}` — an instrument + optional `MetricFilter` string, or an `SloDefinitionId` (soft reference; `SloCommandService.Delete` removes the objective's notes in its one `SaveChanges`) — with `StartsAt`, `EndsAt` (null = ongoing), `AcknowledgedNoise` and `Author`. **Stores only what the operator typed + the author (§1.2)** — no tag values, no payloads; the note text is never logged. **Kept forever** (nothing sweeps them — they are tiny). Validation: `MetricAnnotationValidation.TryValidate` (pure shape: note bounded, filter parses, end > start, other target's fields cleared, `AcknowledgedNoise` cleared on an SLO note, instants → UTC) + `MetricAnnotationValidator.ValidateAsync` (the instrument must be in the registry via `IMetricQueryService.GetInstrumentKindAsync` — stricter than a tile — or the objective must exist via `ISloQueryService.GetObjective`). **Author = the authenticated dashboard user**: `Warp.Dashboard.Endpoints.DashboardUser.Name(HttpContext)` reads `User.Identity.Name` when authenticated (whichever §1.5 gate set it), else `anonymous`, bounded to 200 — never a body field; an edit keeps the creator and logs the editor. **Audit** = the command service's structured `LogInformation` (`Metric annotation {Id} created|updated|deleted by {Author} on {Target} {TargetName}`), the same mechanism as the SLO / board-tile / issue commands (none of those took the user before #333; this is the first audited action that names it). `IMetricAnnotationQueryService`/`IMetricAnnotationCommandService` registered by `AddWarp` (dashboard-only hosts). Read shape: `GetAnnotations(MetricAnnotationQuery { Instrument | SloDefinitionId, From?, To? })` → newest start first, capped at `MaxPerRead` 200 with `IsTruncated`; overlap is `StartsAt < to && (EndsAt == null || EndsAt > from)` (`MetricAnnotationQueries.InWindow`, shared with the board); an instrument read returns every filter.

**Board association:** `GetBoard` issues ONE more statement for the whole board (instrument notes of the tiles' instruments overlapping the window, same cap) and attaches them per tile in memory via `MetricAnnotationMatch.AppliesTo` = same instrument AND `MetricFilter.Overlaps` (no key both filters constrain with patterns that can never match together; `{none}` overlaps only itself) — never a read per tile. The board's note read is capped at `MaxPerRead` (+1 read to set `MetricBoardModel.AnnotationsTruncated`) and ORDERED so the cap drops the notes that cannot change a verdict first: `AcknowledgedNoise && (EndsAt == null || EndsAt >= to)` first (the notes that acknowledge a status), then the other notes active at the window end, then newest — returned newest first.

**Acknowledged noise (decided: annotation-level flag, no tile column):** a Warning/Breaching tile reads `SloState.Acknowledged` while a COVERING `AcknowledgedNoise` note is active at the window's END — **covering ≠ overlapping**: `MetricAnnotationMatch.Covers` = AppliesTo AND (no note filter OR `MetricFilter.Covers(tileFilter)`: every note clause implied by a tile clause on the same key, the tile's pattern equal or narrower via `MetricValuePattern.Includes` — a prefix never includes `{none}`; an unparseable tile filter is never covered). Overlap still decides what is SHOWN ("N notes"); only coverage acknowledges, so a note on one slice (`status=503`, `outcome=error`) cannot excuse a breach in the rest of the tile (`StartsAt < to && (EndsAt null || EndsAt >= to)`, so a past note never masks a fresh problem); `MetricBoardTileResult.UnacknowledgedStatus` keeps the rule's verdict; values/sparklines are NOT changed (the noise events cannot be told apart, so nothing is subtracted); Healthy/NoData untouched; no effect on SLO evaluation (SLOs keep their own ack). **Verdict `board` field:** the verdict response carries `board` = the resolved board's stored name, or null when every board counted.

**Chart and SLO tiles (2026-11-19 spec):** `MetricTileKind` gains `Chart=3`/`Slo=4` (appended, §8.11) and `MetricBoardTile` two nullable columns, `ChartQuery` (≤ 2000) and `SloDefinitionId` (soft reference, no FK, the `MetricAnnotation.SloDefinitionId` precedent) — the whole migration. **Chart** = the metric detail page's URL controls MINUS the range (the board's range drives every tile): `MetricChartQuery.TryNormalize` accepts only `MetricQueryKeys` (`application`/`breakdown`/`filter`/`compare`/`percentile`/`view`/`numerator`/`minmax`/`rate`), rejects `range`/`from`/`to`, unknown or repeated keys and values the page would not read, parses filters with the one `MetricFilter` grammar, and stores the CANONICAL form (keys in `MetricQueryKeys` order, filters by key, defaults out, percent-encoded) so the seeder matches a seeded chart by string equality; the key list mirrors `metricQueryKeys` in `metricModel.ts` and `MetricChartQueryKeysSyncTests` (NoDb) reads that file and fails on drift; the percentile must be one the page draws (`MetricChartQuery.Percentiles` = `PERCENTILES`, 50/90/95/99 — any other the page reads as none, so a tile would render without its line and the editor would drop it; same sync test), and the application is bounded at 200 like every other application field (a tag key at 128). A chart's application and filters live ONLY in the query (its `Application`/`TagFilter` columns stay null); status rule must be None (a picture, never a verdict check). **Per-kind column clearing** (`MetricBoardValidation`, the `SloValidation` rule): Chart and Slo clear every value/ratio/status-rule column; Slo also clears the chart query, application and filter and stores `Instrument` as `""` (non-null column, no migration); Value/Ratio/Chart clear `SloDefinitionId`, Value/Ratio clear `ChartQuery`. An Slo id naming no objective is a 400 (`MetricBoardTileValidator.ObjectiveNotFound`). **12-chart cap** (`MaxChartTiles`, within the 48): each chart is its own `GET metrics/{id}/series` per refresh while value/ratio tiles share one batched read; checked in `MetricBoardCommandService.Upsert` under the `warp:metric-board` lock on an insert, a move, and an edit that turns a tile into a chart (null → 400), by the seeder (skip + Error) and by `MetricBoardOptions.Chart` (throws on a 13th).

**Board read:** charts are never in the batched value read (returned with query, kind and unit, nothing computed; the UI fetches each only while in view, `useInView`, at `seriesRefetchMs`); SLO tiles join ONE `ISloQueryService.GetObjectives` call for the whole board, made ONLY when the board has an SLO tile (statement count flat in tiles), and a tile whose objective is gone reads `Missing = true` (a delete by an older binary mid rolling deploy, a row deleted outside Warp, or a race in a provider-less host where no lock is taken).

**SLO delete cascade:** `SloCommandService.Delete` removes the objective's tiles in the same `SaveChanges` as its annotations, **under the `warp:metric-board` lock** (it writes board tiles; optional `IWarpSqlQueries<TContext>?` ctor param like the board command, `TimeoutException` → route 503), and `MetricBoardCommandService.Upsert` re-checks an SLO tile's objective under that lock (`IMetricBoardCommandService.ObjectiveMissing` = -1 → route 400 `ObjectiveNotFound`, the validator's message): the validator's check runs before the lock, so without both a tile could outlive its objective. Rot guards `Upsert_SloTileWhoseObjectiveWasDeletedAfterValidation_*`, `Delete_ObjectiveWhileATileInsertHoldsTheBoardLock_*` (N=2 `BarrierSignal`), `Delete_ObjectiveWhileTheBoardLockIsHeldPastTheTimeout_*`.

**Seeder:** `Chart(...)` takes typed parameters and builds the query with `MetricChartQuery.Build` (`filter` in `k=v` grammar, converted to the page's `k:v`); matched by name or `SameFields` (which now includes `ChartQuery` and `SloDefinitionId`). `Slo(name, application, label)` resolves the objective at seed time by name OrdinalIgnoreCase + application Ordinal (null matches null), in memory over one objective read made only when an SLO tile is seeded; no match or more than one → Error log, tile skipped; `label` (default the objective's name) is the tile name, needed when the board already has a tile of that name (names are unique per board, `Append` throws).

**Seeder order:** `AddSlo` calls `MetricBoardServiceConfiguration.MoveSeederLast` so the SLO seeder is registered before the board seeder whatever the call order (`AddMetricBoard` after `AddSlo` appends anyway) — this relies on the host starting hosted services sequentially (the default). For `ServicesStartConcurrently = true` or an objective seeded by ANOTHER process, a seed whose objective matches ZERO rows is retried in the background (`MetricBoardSeeder.RetryAsync`: a `PeriodicTimer` on the injected `TimeProvider`, every `MetricBoardSeeds.RetryInterval` = 1 min, at most `MetricBoardSeeds.MaxRetries` = 10 passes, created before `StartAsync` returns, never blocking startup, cancelled by `StopAsync`), re-running the insert-if-absent pass for the still-missing SLO tiles only; first miss = Warning ("will retry"), intermediate misses quiet, Error only after the last pass; an AMBIGUOUS objective (two matches) is Error at once and never retried. Test seams `RetryPassed` (released after each pass) + `Retry` (the task); rot guards `Seeder_ObjectiveSeededAfterTheFirstPass_*`, `Seeder_ObjectiveNeverSeeded_LogsAnErrorOnlyAfterTheLastRetry`, `Seeder_StopAsync_CancelsThePendingRetry` (both DBs, `FakeTimeProvider`, no sleeps).
