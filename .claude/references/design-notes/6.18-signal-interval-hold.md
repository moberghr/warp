# §6.18 — design notes (signal interval hold)

> Full rationale, history, measurements and rot guards behind the condensed rule §6.18 in `.claude/rules/`. Read on demand when changing this area. Verbatim from the pre-split `performance.md` (2026-11-25).

**§6.18** **A signal-woken server task runs at most once per `ServerTaskSignalInterval`** (default 500 ms; `ClusterTaskTimings.HoldAfterRun`, applied cluster-wide by the lease scheduler, §6.23). Every completion flush wakes the `Orchestrator` (about ten times a second per server under load) and every enqueued message the `MessageRouter`, and each pass pays a scope, a lock transaction (which N-1 servers then fail to take), its queries and a bookkeeping update: on a drain profile the server-task loops were about a quarter of a worker process's CPU, the orchestrator alone about an eighth, for jobs with no parent at all. After a pass the loop holds for the rest of the interval (never longer than the task's own interval); a wake arriving meanwhile stays pending on the semaphore, so the next pass runs when the hold ends and no wake is lost. The hold applies only to tasks that have signals (`Heartbeat`, `ScheduledJobActivation` and the other timer-only tasks keep their cadence exactly), it is the rest of the signal interval measured from the START of the run and never longer than the task's own interval (`ClusterTaskTimings.HoldAfterRun`), so folding wakes never lengthens the configured interval, and it waits on the scheduler's `TimeProvider`, which is how `ClusterTaskSchedulerTests` drives it with a fake clock. A continuation or a routed message therefore waits at most the interval. Tasks that rerun immediately after doing work (`RerunImmediately`) skip the hold. `WarpTestServer` sets it to zero; `ContinuationIntegrationTests.GivenTheProductionSignalInterval_WhenAContinuationChainRuns_ThenEachHopIsWokenWithoutTheSweep` runs a continuation chain with the default hold and the sweep minutes away, in both worker modes. The bound holds across servers because a signal task's lease ends with its run (§6.23): a signal on a server that does not hold the task claims it at once after another server's idle scheduled run, instead of waiting for that lease to lapse. Rot guards: `ClusterTaskSchedulerTests.PassAsync_SignalsElsewhereWhileASignaledRunHolds_FoldIntoOneRerun`, `PassAsync_RunOnSchedule_DoesNotHold`.
