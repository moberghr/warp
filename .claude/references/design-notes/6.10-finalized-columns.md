# §6.10 — design notes (finalized columns)

> Full rationale, history, measurements and rot guards behind the condensed rule §6.10 in `.claude/rules/`. Read on demand when changing this area. Verbatim from the pre-split `performance.md` (2026-11-25).

**§6.10** **(Superseded in part by §6.13: the batch no longer goes through the change tracker; the same column list now lives in the provider statements.)** **`CompletionBatch` marks ONLY the columns finalization assigns, and that set moves in lockstep with `WarpDispatcherWorker.BuildFinalization`** (`CurrentState`, `CancellationMode`, `CurrentWorkerId`, `LastKeepAlive`, `ExpireAt`, `HandlerType`, `ScheduleTime`, `Metadata`, and since 8.0 `RunId`, cleared to null). A batched completion arrives on a FRESH scope's context with no original values to diff against, so the `Entry(job).State = Modified` it replaces marked every one of the 21 mapped columns dirty and EF wrote all 20 non-key ones, fifty per flush transaction — including `Message`, the unbounded JSON payload, and eleven other columns finalization never touches (8 of the 20 were assigned at finalization when this was measured; `RunId` makes it nine). Measured with 4 KB payloads in dispatcher mode, 30,000 jobs, three interleaved passes: DB ms/job 0.549 -> 0.455 (-17%), the completion UPDATE itself 5,555 -> 2,233 ms exec (-60%) and 1,253,774 -> 687,511 blocks (-45%) with non-overlapping ranges, throughput unchanged; the benefit scales with payload size and is absent at payload=0. **The quiet direction of this is the dangerous one** — a new field assigned at finalization and NOT added to `MarkFinalizedColumns` is silently never persisted, with no error anywhere. Single-worker mode tracks the entity and diffs, which has its own quiet failure: a column another writer changed on the ROW while the worker held the entity (`CancellationMode`, set by `DeleteJob`) is not a diff when the worker assigns the value the entity already has, so `ClearCancellationMode` marks it modified explicitly. **Rot guard for both: `WorkerPathLockstepTests`** runs one job to rest (completed, failed after a retry, cancelled, parked by an outcome) in each mode and compares every mapped column of the row, read from the EF model so a new column is covered without editing the test; verified to fail when `ExpireAt` is removed from `MarkFinalizedColumns`.
