## 3. Design Patterns in Use

### 1. Everything Is a Job
- [EXTRACTED] One `Job` entity with `JobKind` discriminator (`Job=1, Message=2, Batch=3`); parent/child via `ParentJobId` (referenced in 18 files). Evidence: `src/core/Warp.Core/Data/Enums/JobKind.cs:3-8`, `grep -rl ParentJobId --include='*.cs' src/core | grep -v /obj/ | wc -l`.

### 2. Workers Are Pure Executors
- [EXTRACTED] Fetch/execute lives in `WarpWorkerService<TContext>` (single-worker, `UseDispatcher = false`) and `WarpDispatcher<TContext>` (dispatcher, the default since 8.0). Orchestration, routing, recovery, cleanup are `IServerTask` implementations (14 classes) in `Warp.Worker/Services`. Evidence: `src/core/Warp.Worker/WarpWorkerService.cs:32`, `src/core/Warp.Worker/WarpDispatcher.cs:21`, `src/core/Warp.Worker/Services/IServerTask.cs:18`, `grep -rlE "class \w+.*:.*\bIServerTask\b" --include='*.cs' src/core | grep -v /obj/ | wc -l`.
- [CONVENTION] New orchestration goes into an `IServerTask`, not into the worker classes. Evidence: same files; the worker classes contain no routing/finalization-of-parents logic (Orchestrator: `Services/Orchestrator.cs`, MessageRouter: `Services/MessageRouter.cs`).
- [EXTRACTED] `IServerTask` lives in `Warp.Worker`, not Core. Core-side wake-ups use `ServerTaskSignals<TContext>` (31 files). Evidence: `src/core/Warp.Core/Events/ServerTaskSignals.cs`.

### 7. Server tasks: one scheduler per server, claimed by lease
- [EXTRACTED] Tasks with a `LockKey` are cluster-wide and claimed by `ClusterTaskScheduler` through a `ClusterTask` row; tasks without one (heartbeat) run on `PerServerTaskLoop`; both execute through `ServerTaskRunner`, driven by `ServerTaskHost`. Evidence: `src/core/Warp.Worker/Services/ClusterTaskScheduler.cs`, `PerServerTaskLoop.cs`, `ServerTaskRunner.cs`, `ServerTaskHost.cs`, `src/core/Warp.Core/Data/Entities/ClusterTask.cs`.
- [EXTRACTED] Rolling-deploy bridge code (`LegacyTaskLock`, `LegacyServerPresence`) exists and is marked for removal; treat it as temporary. Evidence: `src/core/Warp.Worker/Services/ServerTaskRunner.cs` (3 files reference `LegacyTaskLock`), `src/core/Warp.Core/LegacyServerPresence.cs`.

### 18. Internal server work runs on a separate `WarpServerContext`
- [EXTRACTED] Autonomous server-internal DB work (worker claim/complete, server tasks, addon stores) uses `IWarpServerContext` / `WarpServerContext<TContext>`, a runtime-only mirror of the Warp model with names read from `TContext`; the user's `TContext` stays the schema owner and is used for outbox publishing, handler scopes, dashboard queries. Evidence: `src/core/Warp.Core/WarpServerContext.cs`, `IWarpServerContext.cs` (35 files), `WarpServerModel.cs:21` (`ExcludeFromMigrations`), `DeferredWarpContext` (8 files).
- [CONVENTION] The worker does not resolve `TContext`. Evidence: `grep -rnE "GetRequiredService<TContext>|GetService<TContext>" --include='*.cs' src/core/Warp.Worker | grep -v /obj/` returns nothing.
